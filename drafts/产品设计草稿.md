## 产品愿景

用逐个按键的点击来narrow筛选可能忘记的快捷键、菜单栏可点击项

## 术语

三个词各管一件事，不再混用：

- **菜单项（menu item）**：对象本体。面板和搜索里的一条可执行项，不管是 App 菜单栏里的命令，还是系统热键。数量说「菜单项数」，不说「条目数」「行数」。
- **快捷键（shortcut）**：某条菜单项的键盘捷径，可以不存在。不存在时留空，不写「无快捷键」。
- **行（row）**：只指视觉位置与布局——第几行、每行显示几个、上下一行、行高、行内右侧。不用它指代对象。

## 面板

提示面板：展示快捷键提示的面板
搜索面板：用于搜索绑定 App 菜单栏菜单项的快捷键、App 快捷键、全局（系统级）快捷键、Apple 菜单栏快捷键的面板

提示面板和搜索面板只能显示其中一个，在任一面板中使用Tab键切换面板；每次打开搜索面板都从空查询开始，不保留上一次输入（选中项、滚动位置、纵向范围一并复位）。**已实现**

## 产品使用入口
用户可选其中一个方式触发KagiPeek提示面板：

1. 「按住」修饰键（延迟触发时长可调：0.3–0.9 秒、步进 0.1 秒）或「连按两次」修饰键触发：触发键从一个下拉里单选，六项：任意修饰键、左 Control、左 Option、左 Command、右 Command、右 Option。

这些触发方式，不能将按键透传给系统或frontmost app。

这一段在设置页里拆成三件东西。**已定**。

一个整体勾选项（设置里叫「启用」修饰键手势）：取消勾选只是不再用手势触发，三个全局快捷键照旧可用——它们是并列入口，不是同一个开关的不同档位。

「按住」和「连按两次」是同一个设置项里的两个互斥选项，不再是并列的两种模式。

触发键收进一个下拉，单选，不接收组合键。六项：任意修饰键、左Control、左Option、左Command、右Command、右Option。Caps Lock 从候选里删掉——它是锁定键，按一下就切状态，拿来当触发键只会添麻烦。留「任意修饰键」是为了老配置不被悄悄收窄：原来按任意修饰键都能出面板，迁移后还是这样。

触发面板的那一次按键不交给前台 App，其余按键照常透传。

配套评审稿：设置页流程图、控件树、运行时判定顺序、旧值到新结构的迁移映射。

2. 全局快捷键触发：设置一个快捷键，在任意位置、任意app上方触发KagiPeek提示面板。

这个快捷键要检测是否与系统快捷键或其他任意app快捷键有冲突

### 光标

光标下有选中项时：
1. 点击Space键将选中项透传给frontmost app（如果有对应菜单项，则告诉frontnost app点击该项；如果只有快捷键（app快捷键、或可在app内生效的全局快捷键），将快捷键透传给frontmost app）并关闭提示面板

按住Shift键同时按下0-9、a-z，则将对应快捷键透传给frontmost app并关闭提示面板。
点击Esc键：关闭提示面板

收藏：添加到收藏夹
复制快捷键：拷贝到系统剪贴板；没有快捷键的菜单项，复制的是菜单路径。**已实现**

### 按键

当用户点击某个按键时：
1. 如果这个按键是修饰键，则将提示面板中的菜单项 narrow 到所有包含该修饰键的快捷键，并将这些菜单项的快捷键里的该修饰键高亮显示，当用户第二次点击该按键时，取消 narrow 和高亮显示，恢复到默认展示状态。
2. 如果这个按键不是修饰键，则将提示面板中的菜单项 narrow 到标题或快捷键中包含该字符（App 设置语言和 English 任意一个匹配上都算数）的菜单项，并把命中的字符高亮显示；字符匹配支持拼音首字母、多字符组合（比如 com op x、cox 代表 command+option+x，顺序不影响结果，op cm x、ocx 同样能匹配到 command+option+x；ex、xe 能匹配到 exit）

如果用户点击第二、第三个修饰键时，同样在之前narrow基础上继续narrow，如果其中某个修饰键第二次被点击则取消基于该修饰键的narrow。

筛选条件是一条有序的 token 队列：先按的修饰键、后敲的字母按先后排着，`⌫` 只弹掉队尾那一个；同一个修饰键重新按下（按下边沿，不是松手）会把它从队列里撤掉，再按一次又加回队尾。松开修饰键，条件不跟着消失。召唤面板的那一次按键不参与筛选，Shift 始终只做提示层、不进队列。**已实现**

修饰键和字母可以组合筛选，语义和搜索一致——查的是同一套语料，不是第二套匹配规则；过滤条件为空时，字母仍然走 chord（拼快捷键），不会被当成筛选字符。**已实现**

### 面板的第二种形态：常驻面板

菜单栏的「快捷键提示面板」把面板钉在屏幕上：不跟随光标，也不会因为移出或失去焦点而关闭。再点一次收起，Esc 也能关。适合对着一个陌生 App 一条条试。

### 两套触发方式，各自开关

触发设置是一行两段：一个勾选框管「修饰键手势」，后面两个下拉选「按住停顿 / 连按两次」和触发键（任意修饰键、左 Control、左 Option、左 Command、右 Command、右 Option，单选，不要 Caps Lock）；另一个勾选框管三条全局快捷键。两套可以同时开、只开一套，也可以都关。

按住停顿默认 0.5 秒，可调 0.3–0.9 秒、步进 0.1 秒；连按两次不单独设窗口，跟随系统“双击速度”并限制在 0.25–0.6 秒，只有两次之间的间隔计时。手势触发的那一下按键不再交给前台 App，取消也不回放；其他键照常透传。

### 搜索面板的边界

搜索会同时看前台 App 的菜单、各 App 的快捷键和系统级快捷键，也可以把范围指定到某一个 App。结果是分页的，排序默认按「用得多」，也可以按标题；可以只看收藏。没有结果、没有权限、扫描没跟上，都会给一句说明，而不是一片空白。

### 面板的可视区域

**页脚永不遮挡菜单项。** 内容区与页脚是上下两块，不是叠层：内容高度 = 面板高度 − 页脚高度（页脚 32pt，标题栏 54pt，分隔线 1pt 都是固定值）。每页行数取 `min(设置值, 几何可容纳行数)`，设置里的「每页行数」只是上限；窗口放不下时宁可少排几行，也不让最后一行落到页脚下面。**已实现**

面板贴近屏幕边缘时整块位移，不硬撑：先按几何算出一页能放几行，再让窗口整体挪进可视区域——贴到底部就整体上移，底部至少留 8pt。可用高度连一行都放不下时，仍保证一行完整可见并整体位移；全屏、或者菜单栏自动隐藏时，面板也必须整块完整可见：顶边避开菜单栏和刘海的安全区，宁可整体往下挪，也不压到屏幕顶。**已实现**

### 面板翻页

翻页键分两层。方向键 ← / → 永久生效，不可关闭，也不进设置；另外有四对可选的字符键，做成多选勾选项——逗号/句号 `, .`、方括号 `[ ]`、减号/等号 `- =`、分号/引号 `; '`。默认只勾分号/引号，四对全不勾也允许，这时只剩方向键。第三对是减号 `-` 和等号 `=`，`+` 不属于任何一对。字符键按字符判断，不按物理键位。设置位置：通用 → 菜单项操作。**已定（多选设置本期不做，代码现在固定认 `;` / `'`）**

到边界继续按会**循环**，不是单向死胡同：最后一页按下一页回到第一页，第一页按上一页跳到最后一页。键盘翻页在边界仍然可用。**已实现**

只有一页的时候，两个翻页键都不产生动作：不重建面板、不闪、不重排，也不会写一条「翻了一页」的日志。页数变少时页码先夹回有效范围，不会停在一个已经不存在的页上。**已实现**

### 收藏与忽略

收藏跨启动保留，可以置顶；筛选时默认不会把收藏藏掉，这个可以关。
忽略的菜单项按标题记，可以全局生效，也可以只对某个 App 生效；被忽略的不会出现在面板和搜索里。

### 排除某个 App

设置里可以整 App 排除：在这个 App 前台时，面板不再弹出。菜单栏那条「排除当前 App」**已搁置**——设置页的能力保留，菜单捷径先不做。

### 使用统计与排序

Return、右键「执行」、点击都会记一次使用次数，按 App 分开算。面板默认让用得多的靠前，也可以改成按标题。设置里能看每个 App 的次数和快捷键数，也能一键清空。

### 冲突检测

扫描系统快捷键和各 App 的配置文件，列出和我们想用的组合重复的项；能按类型、按相关 App 过滤，能就地「试这个组合」，也能手动重扫。

### 权限

把组合键送进前台 App 需要辅助功能；输入监控是兜底。缺辅助功能时菜单栏才出现「权限向导」，补齐后自动消失。权限页能看到两项的状态并发起申请。

### 外观

面板主题三选一：跟随系统、浅色、深色，默认跟随系统。面板排序二选一，用分段控件：按修饰键、按菜单栏分组，默认按修饰键（同一修饰键的菜单项聚在一起）；选按菜单栏分组后，同一顶层菜单（文件、编辑、显示……）的菜单项连续出现，组标题占一条 24pt 的标题条，块与块之间有卡片留白，组内仍按快捷键排。按键显示样式、列数、每页行数、描述长度、按键靠左还是靠右也都能调；面板位置可选覆盖前台窗口、固定长宽、铺满屏幕、贴在前台窗口旁边。改排序时，已打开的面板立即按新顺序重排，不需要重新扫描，并弹一条 HUD 报出当前顺序；汇总面板按修饰键、搜索面板按匹配度，两者都不受面板排序影响。**已实现**

浅色材质用 `.popover`，深色用 `.hudWindow`；外边距 16，行内边距 8，列表上下留白 8/10，窗口圆角 12。**已实现**

**选中行。** 左侧一条 3pt 竖条，底色再提亮一层；VoiceOver 按「名称、快捷键、菜单路径」读，选中态是单独的 trait，不靠颜色或朗读顺序暗示。**已实现**

## 面板输入即搜索（讨论中，未实施）

这一节只记录讨论，不写进代码，也不改 `SearchIndex` / `SearchCorpus` 或面板输入路径。**讨论中 / 暂不实施**——实施前需先定本节末尾的 6 条。

**目标。** 在提示面板里直接打字就做全文匹配，最终把搜索面板的能力并进提示面板，两个入口共用一个匹配器。比如依次输入 `c`、`f`，应当同时命中 ⌘F 的菜单项、标题拼音含 c 或 f 的项、标题原文含 c 或 f 的项，而且**顺序无关**：`cf` 与 `fc` 结果一致。

**现状事实。**

已经具备：`SearchCorpus` 有拼音全拼、拼音首字母、拉丁首字母、chord 渲染、键名 token、修饰键别名、菜单路径逐级减半、四档打分；面板与搜索面板已经在用同一个匹配器。

尚且缺：面板输入的语义仍是「标题前缀」，不是无序全文命中；面板每敲一个键都重建语料（性能负债，实测单键约 12.4ms，搜索路径约 1.19ms）；简繁与全角/U+3000 没有归一化；单字符会带来大量噪音。

反面参考：keycheats 是硬编码表加全子串 AND 匹配，没有打分也没有排序，拼音靠作者手写 `kw`，`⌘c` 连写不命中——不值得照抄。

**已经定下来的技术判断。**

拼音用系统 `CFStringTransform` 的 `mandarinToLatin`，体积 0；多音字误差接受，首字母更稳。

英文描述不做通用提取：实测 Finder / TextEdit 的菜单在代码里构建、包内没有 `MainMenu` 资源；Safari 从 nib 能抓到英文但映射不回 AX 菜单项；Chrome 是专有 `locale.pak`。只保留一份高频词的小型别名表。

## 工程与发布

改动先开新分支，做完合回 main，不直接在 main 上改。**已定**

自用和给别人装是两件事。本机构建继续用本地证书签名就够，同一张证书，辅助功能不会反复问。给别人装走另一条路：Apple Developer Program 的 Developer ID 签名、打开 Hardened Runtime、做公证，从官网或 Homebrew 分发，不上 App Store。**已定（方向）**

签名身份一换，老用户的辅助功能授权会重新问一次。更新说明里要提前写清楚。**已定**

ad-hoc 只用于临时目录里的 `codesign --verify`，不进 `/Applications`：ad-hoc 没有稳定代码身份，每次构建 cdhash 都变，系统会把每次构建当成新 app，权限反复授权、设置里堆僵尸条目。覆盖安装前的旧包统一备份到 `~/Library/Application Support/KagiPeek/backups/`，命名 `KagiPeek-<日期-时间>-<commit>-<local|adhoc|devid>.app`，默认留最近 5 份；`/Applications` 下只保留一份 `KagiPeek.app`。**已定**

版本号没有跟着每次构建往上走，现在用户能看出的差别，是「关于」页里内嵌的 commit：版本行写成 `v2.2.0 (836e3c3)`，括号里是构建时写入的 commit 短哈希，拿不到时写 `unknown`，不再重复显示 `CFBundleVersion`。**已定（现状）**

三档方案——维持自签内测、Developer ID 公证、App Store——的成本与预算在评估。**评估中**，金额先不写进草稿。
