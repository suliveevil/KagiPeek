# Changelog

All notable changes to this project are documented here, in the order the work happened.

## Added

- Initial MVP: global key listening via `CGEventTap`, a modifier state machine, a prefix trie, and a floating overlay panel.
- Static catalog of about 100 common macOS shortcuts.
- Hold-modifier overlay with frequency-based ordering, a multi-column layout, usage statistics, and menu bar controls for triggering the overlay and opening settings.
- Live scanning of the frontmost app's menu bar through the macOS Accessibility API (`AXMenuBar` → `AXMenuBarItem` → `AXMenu` → `AXMenuItem`), reading key equivalents and `AXEnabled` state recursively. Works with any app that exposes a standard menu bar; no per-app shortcut list is required.
- A built-in fallback catalog of roughly 100 system, text-editing, Finder, and screenshot shortcuts, used when an app has no menu bar or a scan cannot run. The catalog can be disabled in Settings.
- Per-app scan cache with a 20 s TTL. Switching the frontmost app forces a fresh scan, app launch/quit clears the cache, and changing the language or built-in-catalog setting refreshes it. There is no live menu observer. Scans run on a background queue with a 0.35 s Accessibility messaging timeout, so the main thread never blocks on a slow app.
- Four trigger modes:
  - hold a ⌃/⌥/⌘ combination and pause (default, 0.1–1.5 s delay, 0.5 s by default);
  - double-tap ⌘ (under 300 ms);
  - a global hotkey (default ⌃⌥⌘K), which keeps the panel open until Esc or the hotkey again;
  - off.
- A which-key panel that supports multi-stroke chords (for example `⌘K ⌘C`) with a breadcrumb, ⌫ to go back one level and Esc to close — both only while no other modifier is held — and that stays in place between strokes. Long lists paginate with `n/m` and clickable ‹ ›, respond to the scroll wheel, and never grow past the screen; long descriptions are truncated to a configurable length with an ellipsis.
- A 0.75 s "executed" HUD (for example `⌘C Copy ✓`) when a shortcut is completed. A key with no matching binding leaves the panel open rather than closing it. Can be disabled.
- Conflict detection: bindings that claim the same key combination are marked ⚠︎, and **Settings → Conflicts** lists them.
- Menu items reported as disabled (`AXEnabled == false`) are greyed out, and can optionally be hidden.
- Ordering for the lists on the statistics page: **Smart order** by default (presses weighted by exponential decay, then raw count), plus most used first, key order, and alphabetical.
- Local usage statistics: use count and last-used time per binding, keyed `bundleID|chord` (`*` for system and built-in rows) so they are grouped by app, with an 800-entry LRU cap and a reset button in Settings. No raw key events or text are stored.
- A global search panel (default ⌃⌥⌘F) with fuzzy search over the current app's menu shortcuts and the built-in catalog, ↑/↓ to select, and Return to run the selected command.
- Panels are anchored to the frontmost window (beside or below it) instead of the fixed top-left corner, and try to avoid the focused control.
- A dark translucent panel that honours **Reduce Transparency** and **Increase Contrast**, with appearance settings for key style, column count, rows per page, description length, key position, theme, and favourite pinning.
- General settings for launch at login, excluding apps by bundle identifier, and ignoring a command title globally or for one app.
- English and Simplified Chinese interface, following the system language with a manual override in Settings.
- Accessibility is the required permission (menu reading, the global key tap, and `AXPress` execution). Input Monitoring is offered as an optional fallback when a system does not deliver key events with Accessibility alone. Each is detected and explained separately. The panel hides automatically while macOS secure input is active.
- The app is an `LSUIElement` menu bar agent (no Dock icon): its menu bar icon opens the panel, the search palette and Settings, and ⌘, opens Settings.
- Pure-logic SwiftPM target `KagiPeekCore` with XCTest coverage for chord parsing, key mapping, prefix matching, ordering, key formatting, description cleanup, conflict detection, search indexing, localization, the built-in catalog, and usage statistics.
- GitHub Actions CI on `macos-15`: `xcodebuild` build with signing disabled plus `swift test`.
- `scripts/build_release.sh`: Release build, Developer ID signing and `notarytool` notarization when available, ad-hoc fallback otherwise, DMG packaging at `build/KagiPeek-<version>.dmg`.
- `scripts/install.sh`: build and replace `/Applications/KagiPeek.app` for local use.
- `Distribution/kagipeek.rb`: Homebrew cask template for a tap.
- **An actionable panel.** ↑/↓ move the row selection, ←/→ page, the run key acts on the selected row, and Esc closes the panel. When the panel consumes these keys they do not reach the front app. Clicking a row does the same thing as the run key, and a row that still has further steps opens the next level.
- **System hotkey conflict detection.** `CopySymbolicHotKeys` (Carbon) is read to collect the enabled system-wide shortcuts (Spotlight, Mission Control, screenshots, input-source switching, …) and compare them with the current app's menu shortcuts. A matching chord is marked ⚠︎, and the conflict list names the system source.
- **A multi-app scope for the search palette.** Its app menu lists the frontmost app plus every running regular app, and its header shows the scoped app's icon and name; choosing another app re-scans and re-ranks for it, and running a row activates that app first. The panel keeps following the real frontmost app.
- **Export Markdown.** The palette's export button opens an `NSSavePanel` and writes what is on screen — the matches, or the scope's whole sheet when the field is empty — as Markdown: grouped by menu, table columns `Shortcut` / `Action`, unavailable items marked `(unavailable)`.
- **Check for updates.** The About tab gains a *Check for updates* button. It requests `https://api.github.com/repos/suliveevil/KagiPeek/releases/latest`, compares the tag with the running version, and shows a link to the release page when a newer version exists, or a short failure message. It is manual only: no automatic download and no background polling.
- New sources: `Core/Services/UpdateChecker.swift`, `Core/AX/SystemHotkeyReader.swift`, `Core/AX/AppDirectory.swift`, `Core/Pure/SemanticVersion.swift`, `Core/Pure/MarkdownExporter.swift`, `Core/Pure/PanelPlacement.swift`, `Core/Pure/HotkeyMatcher.swift`, `Core/Storage/DataDirectory.swift`; `SearchIndex` gains the precomputed `SearchCorpus` and the `Pinyin` helper. `PanelState` gains `selectionIndex` and `flatRowIDs`; `KeyboardMonitor` gains `updateCapturedKeys` so the panel can consume its navigation keys.
- Tests for the ordering modes (stale entries beat never-used ones), `SemanticVersion` parsing and comparison, Markdown table rendering, system-hotkey conflicts, and settings defaults.
- **A persistent panel.** Summoning it — with the hotkey (⌃⌥⌘K), by double-tapping ⌘, or by holding a modifier — leaves it open until you press a complete shortcut, press Esc, or press the panel hotkey again. Releasing the modifiers no longer dismisses it, and there is no idle timer.
- **Progressive highlight.** While modifiers are held, every row whose shortcut starts with them is highlighted. The moment a complete shortcut is pressed, that row's description is emphasised in the accent color for about 0.4 s, then the panel closes. Row selection with ↑/↓ and key highlighting are two different visual states.
- **Hyper-key support.** Hotkey matching allows an event to carry a **superset** of the recorded modifiers when the recorded hotkey has three or more modifiers. A Karabiner-style hyper combination (⌃⌥⇧⌘) therefore matches a recorded ⌃⌥⌘ hotkey. Hotkeys with fewer than three modifiers stay strict.
- **Tokenized search.** Space-separated terms are matched in any order (AND), and `+` works as a separator, so `com op x`, `op cm x`, and `cmd+opt+x` all find ⌘⌥X. Modifier aliases are understood: com/cmd/command/cm/⌘, op/opt/option/alt/⌥, ct/ctl/ctrl/control/⌃, sh/sft/shift/⇧.
- **Pinyin and initials search.** Chinese titles match by full pinyin (jian qie) and by pinyin initials (jq); English titles match by word initials (fs → Find Similar). All terms must match, and better matches still rank first.
- **Panel placement options** under **Settings → Appearance → Panel placement**: cover the front window (default), a fixed width/height, fill the visible screen, or beside the front window (the older behaviour). The cover mode makes the panel larger than the front window in both dimensions and centres it on screen.
- **JSON storage in Application Support.** Settings and statistics live in `~/Library/Application Support/KagiPeek/settings.json` and `usage.json`, written atomically. A file that cannot be decoded is renamed to `*.corrupt-<timestamp>.json` and kept rather than silently discarded. The first launch migrates the previous UserDefaults data, including the earlier `com.Voltline.KagiPeek` domain, exactly once.
- **Guided permission onboarding.** **Request Access** both shows the system authorization prompt and opens the matching System Settings pane (Accessibility or Input Monitoring). The Permissions tab also offers a draggable KagiPeek icon that can be dropped straight into the list in System Settings.
- **A settings window divided by concern.** General, Trigger, Appearance, Statistics, Conflicts, Permissions, Diagnostics and About each have a page of their own. About shows the app icon, version and build number, system version, the manual update check, the data folder (with an open button), the repository and license, and diagnostics (Accessibility, Input Monitoring, listener state, and the number of scanned menu items). Statistics and Conflicts used to share a page, which made each of them hard to find.
- **A switch panel/search hotkey.** A global hotkey, ⌃⌥⌘S by default and recordable in Settings, swaps between the panel and the search palette.
- **Running a shortcut is a recorded key pair.** `runRowKey` (↩ by default) closes the panel and runs that row's command — pressing the menu item when the scan kept one, replaying the chord otherwise — while `copyRowKey` (⌘↩ by default) only writes the chord to the clipboard and leaves the panel open. The search palette is a run-only surface and does not take either key.
- **The search palette carries the app scope and the export.** Looking at another app is the palette's app scope, and Markdown export is a button in the same header, so the separate browser window is no longer needed. The palette's rows are live: hover selects, a click or Return runs, ↑/↓ walk the list, Esc closes — driven by a window-level key monitor that leaves input-method composition alone. What the panel and the palette share is the row builder, the gutter marker and the press flash.
- **The panel is two cards, ordered by the shortcut.** The app's commands come first under its name, the system's hotkeys after them; inside a card rows are ordered by the chord itself (fewer strokes first, then ⌘ → ⌥ → ⌃ → ⇧, then the key, with a function key beside the letter it is named after) and a command with no shortcut sorts last. The menu path is the row's middle column instead of a heading, so no heading can cut the ⌘ block in half.
- **`/` swaps the panel for the palette.** The panel has no text field: `/` opens the palette with the query it was last left with, and `/` again while the field is empty returns to the panel. A typed `/` is still a character.
- **A responsive panel title bar.** The header is measured and lays itself out in three densities — full at 600 pt and above, tight above 460 pt, minimal below — so the settings and close buttons stay clickable in a one-column panel instead of being pushed out of it.
- **Click feedback everywhere.** Every glyph-only control answers the pointer: a soft fill on hover, a quick dip while held, a dimmed body when disabled, plus a press flash on rows. Tooltips on the pager, the clear buttons and the close button.
- **An explicit close button** (`✕`) in the panel title bar for both surfaces, so a mouse user no longer has to guess how the panel goes away.
- **Export diagnostics…** in **Settings → Diagnostics** and **Settings → About** writes one JSON report (permissions, listener state, scan result, settings, the command that prints the matching log lines) to attach to a bug report. `KAGIPEEK_SELFTEST=1` writes the same report and works while the app is already running.
- **Categorised logging** (`os.Logger`, subsystem `com.voltline.kagipeek`, categories `scan`, `input`, `storage`, `ui`), so a failed scan, a refused write or a dropped injection leaves a trace instead of looking like "it stopped working".
- **Conflicts say what kind of clash they are, and who wins.** Every binding sits on a layer of the macOS event stack — `driver` (Karabiner) → `eventTap` (skhd, Keyboard Maestro, BetterTouchTool) → `system` → `globalHotKey` (Hammerspoon, Alfred) → `otherGlobal` → `menuItem` — and lower wins. `ShortcutLayer` reads the *tool*, not just the source, because all six config scanners share `BindingSource.configFile` and would otherwise be ranked next to a menu item. A finding names the two things that collide — menu-order overlap, a system shortcut shadowing a menu item, a tool shadowing a menu item or a system shortcut, system-vs-system, system-vs-tool, tool-vs-tool, or one tool binding the same chord twice — and the verdict is `.winner`, `.tied` or `.menuOrder`; where the honest answer is "same layer, registration order decides, and no file records it", it says that rather than guessing. **Settings → Conflicts** puts the config sources first, then the list with a type filter, a related-app filter, the scan timestamp, a manual rescan and **Test this combo** per row.
- **Third-party shortcut config files are scanned**, so a conflict list can say "⌘⇧4 will never reach Safari" instead of just "two things want ⌘⇧4": Karabiner-Elements (`karabiner.json`, complex modifications with a mandatory modifier), skhd (`skhdrc`), Keyboard Maestro (hot key triggers, inactive macros and groups skipped), BetterTouchTool (newest `btt_data_store.version_*`, opened read-only through SQLite), Hammerspoon (`hs.hotkey.bind` with literal arguments; a variable modifier table is dropped rather than half-resolved) and Alfred (workflow hotkeys, following `prefs.json` for synced preferences). On by default, switchable in **Settings → Conflicts**, scanned at launch and on demand but deliberately not on every app switch. Each parser is a pure function over text/data/plist so it is tested against fixtures.
- **Combo lookup.** Typing a combination into search (`cmd shift 4`, `⌘⇧4`, `opt cmd t`) answers *who owns this* or *it is free*, instead of returning an empty list that reads as "not scanned". A query is only a combo when every token is a modifier or a key, with exactly one key and at least one modifier — which is what keeps `cmd safari` a plain text search. It matches on the same chord key the conflict detector groups by, so the two can never disagree.
- **Live shortcut test.** **Test this combo** in the conflict list watches one real keypress: two listen-only event taps, one at the head of the chain and one at the tail, so a key that arrives at the head and never reaches the tail was swallowed by another app's tap — a fact, not an inference. Above the tap layer it falls back to what came to the front. `LiveTestVerdict` names one of six outcomes with an explicit tone (`confirmed` / `informative` / `inconclusive`) and states its own blind spot: past the tap layer a system shortcut can take a key without leaving a trace. While listening, the engine suspends every panel behaviour and all swallowing, so KagiPeek can never be the thing that ate the key.

## Changed

- Shortcut data source: the primary source is the live menu bar of the frontmost app; the static list is a fallback.
- Bundle identifier changed from `com.Voltline.KagiPeek` to `com.voltline.kagipeek`.
- Minimum macOS version is 14.0 (Sonoma). The earlier project mixed 15.7 and 14 deployment targets; it now uses 14.0 consistently.
- The default sort order is **Smart order**; every other order is still available.
- Conflict detection also considers enabled macOS system shortcuts, and the conflict list shows where each clash comes from.
- The palette header carries an app selector and *Export Markdown*.
- The privacy text states the single manual network request (the update check); everything else remains local.
- **Rows show the complete shortcut.** The panel no longer renders only "the next key": each row lists the full combination, so the display is stable while modifiers are pressed and released.
- **Completing a shortcut lets it through.** KagiPeek highlights the completed row, closes the panel, and lets the key event continue to the front app unchanged; it never synthesizes keystrokes.
- **Panel and search are mutually exclusive.** Only one is visible at a time: opening search closes the panel and vice versa. The switch hotkey moves between them: search visible → panel, panel visible → search, neither → panel.
- **New default placement.** The panel covers the front window by default instead of sitting beside it; the old placement remains available as **Beside the front window**. `attachToFrontWindow` is replaced by the four-value panel placement setting.
- **Settings/statistics no longer use UserDefaults.** Both are plain JSON files in Application Support; the preference domain is read once for migration and is not written any more. Uninstalling or reinstalling the app no longer depends on the preference domain, so data survives unless the folder is deleted.
- **A held modifier narrows the panel.** Summoning by long-pressing ⌃/⌥/⌘ pushes that set onto the prefix, so the panel narrows which-key style; the hotkey and double-⌘ summon it with an empty prefix, where every row is a complete combination. The code comments and the documentation now say so instead of describing the opposite.
- **Esc closes the panel whatever the modifiers are**; ⌫ still backs out one chord stroke and is only handled with no other modifier held.
- **Switching apps or desktops closes the panel** rather than refreshing it in place; summon it again for the new app.
- **The app no longer treats its own activation as a frontmost-app change.** Activating for the search palette or Settings made KagiPeek the frontmost app, and the catalog was rescanned from its own (empty) menu bar — the panel fell back to the built-in catalog and the palette renamed itself "KagiPeek". A scan result from an older request can also no longer overwrite a newer one.
- **Settings and statistics are written once, after a pause, by one writer.** Settings changes coalesce (350 ms) and the write reads the snapshot at fire time; a press is recorded in memory and flushed 1.2 s later on a utility queue, then once more at quit. A failed write is logged instead of silently lost.
- **Key events are decoded lazily.** The tap reads the Unicode string only while a surface is taking keys or a binding is being recorded, and the panel's rows are cached until the prefix, catalog, chips, favourites-only toggle, ignored titles or page size changes.
- **The conflict list is typed rather than flat.** It used to print "%d chords are bound more than once" and a bullet per member, which invites the question *so which one fires?* and could not answer it. It now carries a type badge, the layer verdict, a per-member badge, the two filters and a **Test this combo** button, and it is built from a cache instead of rescanning every app each time the page opens.
- **Row interactions live in testable pure code**: `RowKeyRouter` (run before copy, one implementation for the panel and the palette), `PanelRowBuilder`, `HeaderLayout`, `PanelOrdering`, `PanelSections`, `PanelSelection`, `PanelKeyIntake`, `PendingModifiers`, `ChordComposition` and `PanelState`.

## Removed

- **The static list as the only source.** The 100-entry catalog became a fallback behind live menu scanning.
- **The fixed top-left overlay placement**, replaced by anchoring to the frontmost window.
- **The auto-hide delay / 自动关闭延时已移除。** The `autoHideDelay` setting and its model field are removed from the app, not hidden behind a default: no panel times out any more. A panel closes only when you press a complete shortcut, press Esc, or press the panel (or switch) hotkey again.
- **The "next key only" row label.** Rows render the complete combination.
- **The pinned/unpinned panel distinction**, including the separate auto-close rules for browse panels.
- **Both "Execute menu commands" switches.** `allowPanelExecute` and `allowSearchExecute` never controlled anything after rows started replaying their chord: the first had no callers, the second only switched one footer sentence — and it was wrong, telling users Return copies while Return ran. With them go `PanelState.allowsExecution`, `PanelState.appCanExecute`, `execute(rowID:)`, `HotkeySpec.isValid`, `.searchHint`, `.searchCopied` and `.browserExportDone`.
- **Dead state and dead keys.** `PanelState.highlightedRowIDs` had no readers, and `KeyToken("fdelete")` became a constant.
- **The browser window.** Its two jobs moved into the search palette (app scope and Markdown export), so the window, its key monitor and its refresh button are gone.
- **The review sort mode.** `RankMode.review` ordered the statistics page by "least recently used first" — a second, weaker way to ask the question `smart` already answers with decayed usefulness — so the mode, its menu entry, its two strings and its two tests are gone. A settings file that still says `"review"` decodes to `smart`: a throwing decode would take the whole document with it. The default mode keeps its behaviour and loses the vocabulary: it is now **Smart order** / **智能排序**.

## Fixed

- **System hotkeys say what they do.** Every row under *System hotkeys* read `⌘M … ⌘M`: macOS ships a `kHISymbolicHotKeyDescription` field that is empty for all 233 entries, so the reader had nothing to print and fell back to the chord itself. The names now come from `SystemHotkeyNames`, a table of the assignments a stock Mac registers (⌘Space → Spotlight, ⌃↑ → Mission Control, ⇧⌘3 → Screenshot, ⌥⌘⎋ → Force Quit, ⌘M → Minimize, …), answered in the interface language — 27 of the 79 entries this Mac reports were recognised. The rest — a chord you reassigned, or one of the slots macOS registers with nothing behind it (⌃F1, ⌃⌘D) — show **—** instead of the chord repeated as its own description, and a sequence that merely *starts* with a known chord is never given that chord's name. The middle column stays empty for these rows rather than printing the group title 79 times down the list.
- **Clicking away no longer clicks through.** Dismissing the panel by clicking outside it closed it *and* clicked whatever sat behind it in the app you were working in — moving the insertion point, changing the selection, pressing a button you never aimed at. That one press is swallowed now. Only presses that would land in the front app's window are: a click on the menu bar, the Dock, the desktop or another app's window is you reaching for something else, and eating it would make the panel feel like it had frozen the screen. Presses on the panel itself are the panel's, as before.
- **The pointer comes back.** Summoning the panel never moved the pointer, but leaving it did: clicking a row to run it, or clicking away to dismiss the panel, left the pointer wherever the panel sent it, and the place you were working in the app behind it was gone. The position is remembered when the panel opens and restored when it closes — by Esc, by running a command, by clicking away, by switching apps, all of them. If the pointer never moved (opened by hotkey, dismissed by Esc) nothing is warped, because moving it to where it already is only announces a jump. Opening the search palette from the panel keeps the pointer where it is; that surface is about to want it.
- **Tapping a modifier ticks it.** Only *holding* a modifier narrowed the list, so the Emacs spelling — ⌥, ⌘, C, one key at a time — never worked; releasing the key put the full list back. A press-and-release inside 0.35 s, with nothing typed while it was down, now leaves the modifier ticked, and each further tap narrows on top of the last. Holding still narrows temporarily: holding is looking, tapping is composing. A modifier that was used *with* a key (the ⌘ of ⌘C) is not a tap, and neither is the one still down when the panel opens — that one is the trigger.
- **⌫ undoes the tick you made last.** It removed whichever modifier came last in ⌃⌥⇧⌘ order instead of the most recently ticked one, so ticking ⌘ then ⌥ and pressing ⌫ dropped the wrong one. The ticks keep their order now. Nothing else changes: with no tick left, ⌫ still goes up one level of a chord, and the panel stays open either way.
- **The menu bar icon is visible on a dark menu bar.** `Image(nsImage:)` does not inherit `NSImage.isTemplate`, so the glyph was drawn in its own colour — black — and vanished into a dark menu bar. It is explicitly marked as a template now.
- **Escape closes the panel again** — on the built-in key and on a Caps Lock remapped to Escape by Karabiner. Escape, Tab, Return and Delete each carry a control character (`U+001B`, `U+0009`, `U+000D`, `U+007F`), and the key mapper preferred the character over the virtual key code, so Escape resolved to `U+001B` and was never equal to `esc`; the tap swallowed the press and nothing happened. Tab and Return had the same bug from the other direction — both resolved to `space`. Control characters now fall through to the key code, and the panel recognises Escape by key code, which is also how the tap claims it.
- **⌫ undoes a tick and pops a level again.** Its token is `delete`, which never matched while the key was resolving to `U+007F`, so the key had been inert since it was written.
- **The panel no longer changes height while you narrow the list.** Holding a modifier removes rows, and the window was sized from the rows on screen, so it shrank on every press and grew back on release. It is sized from the session's widest list now.
- **The panel title is no longer a close button.** Clicking the app icon or the app name dismissed the surface silently; the identity block is static now and closing has its own button.
- **Dimmed rows no longer show a selection marker.** They carry `index == -1`, which is also the "nothing selected" sentinel, so `selectionIndex == row.index` lit up every dimmed row whenever nothing was selected.
- **Rows no longer shift when hovered.** The marker and the pin star were inserted into the row's stack, pushing the title and keycap sideways as the pointer moved; both now sit in reserved space.
- **The pin star can no longer fire the shortcut.** A star click inside a row with a tap gesture could also run the row and inject its chord; it is a bounded child gesture now.
- **Pager buttons are clickable** (22 × 22 instead of the glyph's own ~10 pt), and decorative strokes are explicitly out of the click path.
- **The inline filter clears in the snapshot too.** Leaving the filter left `isFiltering`/`filterText` set, so the UI kept drawing a filter bar for a filter that was no longer active.
- **The search palette no longer swallows ⌃⌥P or ⌃⌘P.** It passed a hard-coded ⌃ to the navigation matcher, so any combination containing ⌃ plus P/N was treated as navigation and consumed.
- **Held keys no longer leak or repeat.** Repeats of a key the panel consumes are consumed too, running a row no longer repeats while the key is held, and ⌘⌫ / ⌥⌫ are consumed while the inline filter is open instead of deleting in two places.
- **Settings no longer lose a change to a concurrent write** (two writers within the debounce window used to be last-wins).
- **The panel highlights the rows on the page.** `highlightedIDs(for:)` discarded its page argument and recomputed the same prefix over the whole catalog.

## Upgrade notes

- **Accessibility must be granted once.** If the bundle identifier or the code signature changed — a local or ad-hoc rebuild, or an install over a release signed by another identity — macOS sees a new app: open **System Settings → Privacy & Security → Accessibility**, remove the stale KagiPeek entry if present, and enable the new app. Grant Input Monitoring too only if the panel does not appear after that. See [docs/PERMISSIONS.md](docs/PERMISSIONS.md).
- **macOS 14.0 is required.** The app does not run on macOS 13 or earlier.
- **The panel does not close by itself.** If you expected it to disappear after a few seconds, press Esc (or complete a shortcut). There is no auto-hide setting to configure.
- **The trigger is not a prefix in the hotkey and double-⌘ paths.** The panel lists the app's full shortcut set and highlights the rows that start with the modifiers you hold; summoning by a long modifier press seeds that set as a prefix instead. To run a row with the keyboard, use ↑/↓ and Return, or type the complete shortcut.
- **The default placement is Cover the front window.** Pick **Beside the front window** in **Settings → Appearance** to restore the old behaviour, or choose a fixed size or full screen.
- **Settings and statistics move on first launch.** KagiPeek reads `settings.json`/`usage.json` if present, otherwise migrates the previous `settings.v2`/`usage.v2` UserDefaults payloads, otherwise the older `com.Voltline.KagiPeek` domain. The old defaults are left in place and can be deleted with `defaults delete com.voltline.kagipeek` and `defaults delete com.Voltline.KagiPeek`.
- **Statistics are grouped by app.** Existing `bundleID|chord` keys are reused, so history carries over; the Statistics tab lists presses per app, and system/built-in shortcuts appear as **System / built-in**.
- **Hyper keys need no extra setup.** Record a three-modifier hotkey as usual; a tool that adds a fourth modifier still matches it.
- **Replacing an existing install with an ad-hoc signed local build invalidates the privacy grant** because the signature changes; remove the old Accessibility entry and re-add the new app. The same applies when replacing one build with another signed by a different identity.
- The app remains sandbox-free and is not distributed through the Mac App Store.
