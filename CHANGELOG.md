# Changelog

All notable changes to this project are documented here, in the order the work happened.

## [Unreleased]

### Added

- **The ⇧ chip in the title bar names both of its paths.** Clicking the chip ticks ⇧ into the modifier filter; pressing ⇧ on the keyboard flips the hint layer and never adds a filter token, because capital letters arrive with ⇧ down and `ShortcutEngine` keeps it out of the token list. One tooltip on the whole chip row could only describe the case the four keys agree on, so the tooltip moved from the row onto each chip and ⇧ got its own sentence — *click to add ⇧ to the filter; press ⇧ on the keyboard to open the hint layer* — carried both as `help` and as the accessibility hint, since VoiceOver never hovers. ⌃ ⌥ ⌘ keep the previous text.

### Fixed

- **Launching a second copy no longer erases the running copy's crash sentinel.** The sentinel `logs/session.active` was written in `init`, before the single-instance guard ran, and the clean-exit path deleted it on the strength of the file existing. So a double launch — or `open -a` on the installed build while it was already running, or a diagnostics run — overwrote the live instance's file with its own pid, logged `previous session ended unexpectedly` about a process that was still running, and then deleted the file on its way out. The live instance was left with no sentinel, so a later kill went unreported. The sentinel now records an owner: a launch that finds a live pid reports nothing, claims nothing and deletes nothing, and a clean exit removes only a file this process wrote (`SentinelOwnership`). A sentinel with no pid (an older file) keeps the previous verdict.
- **A failed sentinel delete is no longer swallowed.** Writing the sentinel has always warned about its own failure; deleting it used `try?`, and a delete that fails leaves behind exactly the file that makes the next launch report an unexpected exit that never happened. It now logs `could not delete the sentinel …` instead. The duplicate-launch path also no longer clears the shared `last-actions.json` mirror.
- **Quitting no longer hangs on a stuck `karabiner_cli`, and the last edit still reaches disk.** The bridge waited for the child process with no timeout, and both store flushes were queued *behind* it: a Karabiner daemon that stopped answering held the quit open and dropped the settings and usage edits still inside their debounce window. Each `karabiner_cli` run is now capped at 0.8 s and terminated on timeout, `usage.json`'s flush at 0.5 s, and the two flushes moved ahead of the engine shutdown. The self-test path also stopped running the shutdown sequence twice.
- **Settings opens on the desktop the menu bar item was clicked on, not over a full-screen app.** A window belongs to the Space it was last ordered into, and a menu bar extra is never the active app, so the window lived in whichever Space it had last had a window — a full-screen app's often enough — and ordering it front from the menu bar switched the user to that Space. The window now carries `.moveToActiveSpace`, and one left visible on another Space is ordered out first so that re-parenting actually applies; `.fullScreenAuxiliary` covers the same click made from a full-screen Space, where the active Space belongs to another process.
- **The menu bar's Shortcut Panel item opens the panel again.** It did nothing. The item's action is dispatched while the status menu carrying it is still the popup on screen, and the cross-process popup guard — written so Kaname never covers another app's menu mid-selection — dropped the request every time. The guard now ignores menus owned by Kaname itself (`PopupGate.menuPresent(excludingOwner:)`), and only this menu item passes that exception; a foreign menu, or a sheet or dialog in the front app, still stops the panel.
- **The permission window opens on the Space it was asked for, too.** It was built like the Settings window — created once, ordered front from the menu bar — and had the same Space to land in: a menu bar extra is never the active app, so a window last shown on a full-screen Space was restored there instead of over the desktop it was clicked from. It now carries the same `.moveToActiveSpace` / `.fullScreenAuxiliary` pair and orders itself out first when it is visible on another Space, which is what lets `.moveToActiveSpace` apply. As a sheet it follows its parent window either way; the behaviour sleeps in that form.

## Kaname 2.3.2 (2026-11-07)

### Added

- **The documentation is bilingual, page for page.** `docs/` split into `docs/en/` and `docs/zh-CN/`, each holding the same 16 file names: the 15 pages that were there — 8 English, 7 already Chinese — plus the release notes, which moved to `docs/en/releases/` and `docs/zh-CN/releases/`. Every page opens with a language switch line, and the half that did not exist was written, about 4,200 lines in both directions. Relative links were recomputed for the extra directory depth; `README.md`, `README.zh-CN.md`, `AGENTS.md`, this file, the reports' "prior documents" lists and `publish_release.sh` follow the new paths. The old `docs/*.md` paths are gone with no redirect, so external links to them break.
- Parity is measured per page, not eyeballed: heading count, table-row count, code-fence count and link count match between the two halves on all 16 pages.

### Fixed

- **The modifier chips in the title bar light up while a held key is narrowing the list.** The chips read `heldModifiers` and `latchedModifiers` separately while the glyphs inside each row's chord read `pending.effective`, so a held filter lit the rows but left the chip merely "less grey". Both now read `pending.effective`; a tick keeps its stronger fill and outline, so "sticky" still reads differently from "down right now", and `.isSelected` stays on the tick alone so VoiceOver does not announce a transient hold as a checked option. Three tests in `PendingModifiersTests` pin the filter-token path, the popped token and the held ⇧ case.

### Changed

- A sepia prose pass ran over the new half. It found no banned vocabulary or formula phrasing in either language and changed two things: the English ARCHITECTURE page lost most of its "which is why" and "there is no ..." sentence templates, and the round-2 review report lost a closing recap paragraph whose three facts live in its N12/N13 sections.

## Kaname 2.3.1 (2026-11-06)

### Added

- **A Karabiner rule can stand down while the panel is open.** Karabiner rewrites the keyboard below the event tap, so a rule bound to the trigger key (a `left_command` with `to_if_alone`, typically) kept firing while the panel was up, and the panel only ever saw the rule's output: a lone ⌘ arrived as that rule's shortcut and never joined the filter. **Settings → Trigger → Tell Karabiner when the panel is open** now writes Karabiner's `kaname_panel` variable — 1 while the panel is shown, 0 when it closes, and 0 at launch and at quit so a crash cannot leave a rule suppressed — and a rule carrying `conditions: [{"type": "variable_unless", "name": "kaname_panel", "value": 1}]` applies only while the panel is closed. On by default, silent when Karabiner is not installed, and settings schema 10 → 11 (`karabinerPanelSignalEnabled`). The variable is written through `/Library/Application Support/org.pqrs/Karabiner-Elements/bin/karabiner_cli`, once per state change, off the main thread.

## Kaname 2.3.0 (2026-11-06)

### Changed

- **KagiPeek is now Kaname, end to end.** The project container, source tree, SwiftPM module, bundle identifier (`com.suliveevil.kaname`), signing identity, data folder and scripts all use the new name. To macOS an old KagiPeek install is a different app: Accessibility, Input Monitoring and the login item have to be granted or cleared again for Kaname.
- **Settings was rebuilt across General, Trigger, Appearance and Statistics.** Trigger switches moved beside their section headings, the general toggles folded into the ignored-menu-items card, layout numbers became typed inputs, and statistics flattened to one row per usage key with a sort field (settings schema 9 → 10). Diagnostics later folded into General, leaving seven tabs.
- **A design-review pass tightened the UI.** Type sizes collapsed to five system-scale tokens, corner radii to four tokens on an 8 pt grid, disabled rows gained a dedicated colour plus a non-colour marker, empty panel states gained icons and next-step hints, bare symbols and colour-only states got spoken labels, and the settings window follows the panel's title with zoom disabled.
- **Release builds are non-interactive again.** `build_release.sh` unlocks `kaname-signing.keychain-db` like the swiftc path does and removes `*.cstemp` left behind by an interrupted `codesign`.
- **The run key is Space and the copy key is Return.** Running a row and copying its chord were ↩ and ⌘↩; they are now the two keys people already press on a selected item. A stored pair that still matches both old defaults is migrated on the next launch, and anything recorded by hand wins.
- **The panel carries a third group of cards: the config-file shortcuts.** Karabiner, skhd, Keyboard Maestro, BetterTouchTool, Hammerspoon and Alfred each get one card, folded until its heading is clicked, with its row count on the heading. Those rows can be searched, copied and favourited, and they never run: clicking one copies its chord.
- **Coming back to an app asks the disk cache first.** A cached menu scan is good for ten minutes, so re-opening the panel for an app — or relaunching Kaname — shows its menus without walking the menu bar again.
- **Both diagnostics exports live on the Diagnostics tab.** *Export diagnostics archive…* writes the `.zip`, *Export diagnostics report…* writes the single JSON report that used to sit on the About tab. About keeps the version, the data folder and the update check.
- **CI checks two toolchains.** Every push and pull request builds and tests on `macos-15` and `macos-26`, so a compiler-only regression shows up as one leg failing. Packaging is verified on `macos-15`.

### Fixed

- **A log line that says nothing is now impossible to write by accident.** Diagnostics go through one façade (`Diag`); the four `os.Logger` categories are its private mirror. Before, a second façade looked identical at the call site but never reached the file, which is how "the keyboard froze and the log says nothing" could be both true and useless.

## Panel placement against the front window (2026-11-04)

- The hint panel keeps covering the window: widening it for a tall window recomputes the content height, but the larger of that and the cover height wins, so a short list can no longer shrink the panel below the window. It stays centred on the visible frame.
- The search palette now belongs to the front window instead of the screen: its width stays 680 pt, its height follows the window (clamped to the visible frame), and its centre is the window's centre, clamped so it stays on screen. With no window frame it falls back to the screen centre.
- The first panel after switching apps covers the front window immediately. The window frame is read asynchronously, so the panel used to open at a shrunken 80 % × 70 % guess and only resize on the next presentation — in practice after the modifier was released. It now opens on the whole visible frame and, when the frame arrives, is resized by the same rule as a normal presentation, so the panel is never smaller than the window it covers.

## Automatic double-tap window (2026-11-04)

- The double-tap trigger no longer has an interval setting. Its window follows the system double-click speed, clamped to 0.25–0.6 s.
- Only the gap between the two taps is timed. A slow press still counts as a tap, and a long second press still completes; the gesture is "two clean taps with nothing in between", not "two taps in under 0.3 s".
- Settings v7 removes `doubleTapWindow`; an old value is ignored and dropped on the next save. The Diagnostics page shows the effective window.

## Trigger settings v5 (2026-11-04)

- Trigger settings are now two independently switchable paths: the modifier gesture and the three global hotkeys. Either can be live, both can, or both can be off — both off is the pause state.
- The gesture chooses **hold still** (default) or **press twice**, plus one trigger key: any non-Shift modifier, Left Control, Left Option, Left Command, Right Command (default), or Right Option. Caps Lock is not offered and combinations are not supported.
- Hold delay is 0.3–0.9 s in 0.1 s steps.
- While the gesture is live the trigger key's press and release are swallowed, so the front app never sees the modifier edge; a cancelled hold is not replayed. Shift and Caps Lock are never swallowed.
- Settings v5 migration maps the four old trigger modes onto the two switches; the legacy `triggerMode` key is decoded once and never written back.

## Added

- Initial MVP: global key listening via `CGEventTap`, a modifier state machine, a prefix trie, and a floating overlay panel.
- Static catalog of about 100 common macOS shortcuts.
- Hold-modifier overlay with frequency-based ordering, a multi-column layout, usage statistics, and menu bar controls for triggering the overlay and opening settings.
- Live scanning of the frontmost app's menu bar through the macOS Accessibility API (`AXMenuBar` → `AXMenuBarItem` → `AXMenu` → `AXMenuItem`), reading key equivalents and `AXEnabled` state recursively. Works with any app that exposes a standard menu bar; no per-app shortcut list is required.
- A built-in fallback catalog of roughly 100 system, text-editing, Finder, and screenshot shortcuts, used when an app has no menu bar or a scan cannot run. The catalog can be disabled in Settings.
- Per-app scan cache with a 20 s TTL. Switching the frontmost app forces a fresh scan, app launch/quit clears the cache, and changing the language or built-in-catalog setting refreshes it. There is no live menu observer. Scans run on a background queue with a 0.35 s Accessibility messaging timeout, so the main thread never blocks on a slow app.
- Four trigger modes:
  - hold a ⌃/⌥/⌘ combination and pause (default, 0.1–1.5 s delay, 0.5 s by default);
  - double-tap ⌘ (under 300 ms);
  - a global hotkey (default ⌃⌥⌘K), which keeps the panel open until Esc or the hotkey again;
  - off.
- A which-key panel that supports multi-stroke chords (for example `⌘K ⌘C`) with a breadcrumb, ⌫ to go back one level and Esc to close — both only while no other modifier is held — and that stays in place between strokes. Long lists paginate with `n/m` and clickable ‹ ›, respond to the scroll wheel, and never grow past the screen; long descriptions are truncated to a configurable length with an ellipsis.
- A 0.75 s "executed" HUD (for example `⌘C Copy ✓`) when a shortcut is completed. A key with no matching binding leaves the panel open rather than closing it. Can be disabled.
- Conflict detection: bindings that claim the same key combination are marked ⚠︎, and **Settings → Conflicts** lists them.
- Menu items reported as disabled (`AXEnabled == false`) are greyed out, and can optionally be hidden.
- Ordering for the lists on the statistics page: **Smart order** by default (presses weighted by exponential decay, then raw count), plus most used first, key order, and alphabetical.
- Local usage statistics: use count and last-used time per binding, keyed `bundleID|chord` (`*` for system and built-in rows) so they are grouped by app, with an 800-entry LRU cap and a reset button in Settings. No raw key events or text are stored.
- A global search panel (default ⌃⌥⌘F) with fuzzy search over the current app's menu shortcuts and the built-in catalog, ↑/↓ to select, and Return to run the selected command.
- Panels are anchored to the frontmost window (beside or below it) instead of the fixed top-left corner, and try to avoid the focused control.
- A dark translucent panel that honours **Reduce Transparency** and **Increase Contrast**, with appearance settings for key style, column count, rows per page, description length, key position, theme, and favourite pinning.
- General settings for launch at login, excluding apps by bundle identifier, and ignoring a command title globally or for one app.
- English and Simplified Chinese interface, following the system language with a manual override in Settings.
- Accessibility is the required permission (menu reading, the global key tap, and `AXPress` execution). Input Monitoring is offered as an optional fallback when a system does not deliver key events with Accessibility alone. Each is detected and explained separately. The panel hides automatically while macOS secure input is active.
- The app is an `LSUIElement` menu bar agent (no Dock icon): its menu bar icon opens the panel, the search palette and Settings, and ⌘, opens Settings.
- Pure-logic SwiftPM target `KanameCore` with XCTest coverage for chord parsing, key mapping, prefix matching, ordering, key formatting, description cleanup, conflict detection, search indexing, localization, the built-in catalog, and usage statistics.
- GitHub Actions CI on `macos-15`: `xcodebuild` build with signing disabled plus `swift test`.
- `scripts/build_release.sh`: Release build, Developer ID signing and `notarytool` notarization when available, ad-hoc fallback otherwise, DMG packaging at `build/Kaname-<version>.dmg`.
- `scripts/install.sh`: build and replace `/Applications/Kaname.app` for local use.
- `Distribution/kaname.rb`: Homebrew cask template for a tap.
- **An actionable panel.** ↑/↓ move the row selection, ←/→ page, the run key acts on the selected row, and Esc closes the panel. When the panel consumes these keys they do not reach the front app. Clicking a row does the same thing as the run key, and a row that still has further steps opens the next level.
- **System hotkey conflict detection.** `CopySymbolicHotKeys` (Carbon) is read to collect the enabled system-wide shortcuts (Spotlight, Mission Control, screenshots, input-source switching, …) and compare them with the current app's menu shortcuts. A matching chord is marked ⚠︎, and the conflict list names the system source.
- **A multi-app scope for the search palette.** Its app menu lists the frontmost app plus every running regular app, and its header shows the scoped app's icon and name; choosing another app re-scans and re-ranks for it, and running a row activates that app first. The panel keeps following the real frontmost app.
- **Export Markdown.** The palette's export button opens an `NSSavePanel` and writes what is on screen — the matches, or the scope's whole sheet when the field is empty — as Markdown: grouped by menu, table columns `Shortcut` / `Action`, unavailable items marked `(unavailable)`.
- **Check for updates.** The About tab gains a *Check for updates* button. It requests `https://api.github.com/repos/suliveevil/Kaname/releases/latest`, compares the tag with the running version, and shows a link to the release page when a newer version exists, or a short failure message. It is manual only: no automatic download and no background polling.
- New sources: `Core/Services/UpdateChecker.swift`, `Core/AX/SystemHotkeyReader.swift`, `Core/AX/AppDirectory.swift`, `Core/Pure/SemanticVersion.swift`, `Core/Pure/MarkdownExporter.swift`, `Core/Pure/PanelPlacement.swift`, `Core/Pure/HotkeyMatcher.swift`, `Core/Storage/DataDirectory.swift`; `SearchIndex` gains the precomputed `SearchCorpus` and the `Pinyin` helper. `PanelState` gains `selectionIndex` and `flatRowIDs`; `KeyboardMonitor` gains `updateCapturedKeys` so the panel can consume its navigation keys.
- Tests for the ordering modes (stale entries beat never-used ones), `SemanticVersion` parsing and comparison, Markdown table rendering, system-hotkey conflicts, and settings defaults.
- **A persistent panel.** Summoning it — with the hotkey (⌃⌥⌘K), by double-tapping ⌘, or by holding a modifier — leaves it open until you press a complete shortcut, press Esc, or press the panel hotkey again. Releasing the modifiers no longer dismisses it, and there is no idle timer.
- **Progressive highlight.** While modifiers are held, every row whose shortcut starts with them is highlighted. The moment a complete shortcut is pressed, that row's description is emphasised in the accent color for about 0.4 s, then the panel closes. Row selection with ↑/↓ and key highlighting are two different visual states.
- **Hyper-key support.** Hotkey matching allows an event to carry a **superset** of the recorded modifiers when the recorded hotkey has three or more modifiers. A Karabiner-style hyper combination (⌃⌥⇧⌘) therefore matches a recorded ⌃⌥⌘ hotkey. Hotkeys with fewer than three modifiers stay strict.
- **Tokenized search.** Space-separated terms are matched in any order (AND), and `+` works as a separator, so `com op x`, `op cm x`, and `cmd+opt+x` all find ⌘⌥X. Modifier aliases are understood: com/cmd/command/cm/⌘, op/opt/option/alt/⌥, ct/ctl/ctrl/control/⌃, sh/sft/shift/⇧.
- **Pinyin and initials search.** Chinese titles match by full pinyin (jian qie) and by pinyin initials (jq); English titles match by word initials (fs → Find Similar). All terms must match, and better matches still rank first.
- **Panel placement options** under **Settings → Appearance → Panel placement**: cover the front window (default), a fixed width/height, fill the visible screen, or beside the front window (the older behaviour). The cover mode makes the panel larger than the front window in both dimensions and centres it on screen.
- **JSON storage in Application Support.** Settings and statistics live in `~/Library/Application Support/Kaname/settings.json` and `usage.json`, written atomically. A file that cannot be decoded is renamed to `*.corrupt-<timestamp>.json` and kept rather than silently discarded. The first launch migrates the previous UserDefaults data, including the earlier `com.suliveevil.kaname` domain, exactly once.
- **Guided permission onboarding.** **Request Access** both shows the system authorization prompt and opens the matching System Settings pane (Accessibility or Input Monitoring). The Permissions tab also offers a draggable Kaname icon that can be dropped straight into the list in System Settings.
- **A settings window divided by concern.** General, Trigger, Appearance, Statistics, Conflicts, Permissions, Diagnostics and About each have a page of their own. About shows the app icon, version and build number, system version, the manual update check, the data folder (with an open button), the repository and license, and diagnostics (Accessibility, Input Monitoring, listener state, and the number of scanned menu items). Statistics and Conflicts used to share a page, which made each of them hard to find.
- **A switch panel/search hotkey.** A global hotkey, ⌃⌥⌘S by default and recordable in Settings, swaps between the panel and the search palette.
- **Running a shortcut is a recorded key pair.** `runRowKey` (↩ by default) closes the panel and runs that row's command — pressing the menu item when the scan kept one, replaying the chord otherwise — while `copyRowKey` (⌘↩ by default) only writes the chord to the clipboard and leaves the panel open. The search palette is a run-only surface and does not take either key.
- **The search palette carries the app scope and the export.** Looking at another app is the palette's app scope, and Markdown export is a button in the same header, so the separate browser window is no longer needed. The palette's rows are live: hover selects, a click or Return runs, ↑/↓ walk the list, Esc closes — driven by a window-level key monitor that leaves input-method composition alone. What the panel and the palette share is the row builder, the gutter marker and the press flash.
- **The panel is two cards, ordered by the shortcut.** The app's commands come first under its name, the system's hotkeys after them; inside a card rows are ordered by the chord itself (fewer strokes first, then ⌘ → ⌥ → ⌃ → ⇧, then the key, with a function key beside the letter it is named after) and a command with no shortcut sorts last. The menu path is the row's middle column instead of a heading, so no heading can cut the ⌘ block in half.
- **`/` swaps the panel for the palette.** The panel has no text field: `/` opens the palette with the query it was last left with, and `/` again while the field is empty returns to the panel. A typed `/` is still a character.
- **A responsive panel title bar.** The header is measured and lays itself out in three densities — full at 600 pt and above, tight above 460 pt, minimal below — so the settings and close buttons stay clickable in a one-column panel instead of being pushed out of it.
- **Click feedback everywhere.** Every glyph-only control answers the pointer: a soft fill on hover, a quick dip while held, a dimmed body when disabled, plus a press flash on rows. Tooltips on the pager, the clear buttons and the close button.
- **An explicit close button** (`✕`) in the panel title bar for both surfaces, so a mouse user no longer has to guess how the panel goes away.
- **Export diagnostics…** in **Settings → Diagnostics** and **Settings → About** writes one JSON report (permissions, listener state, scan result, settings, the command that prints the matching log lines) to attach to a bug report. `KANAME_SELFTEST=1` writes the same report and works while the app is already running.
- **Categorised logging** (`os.Logger`, subsystem `com.suliveevil.kaname`, categories `scan`, `input`, `storage`, `ui`), so a failed scan, a refused write or a dropped injection leaves a trace instead of looking like "it stopped working".
- **Conflicts say what kind of clash they are, and who wins.** Every binding sits on a layer of the macOS event stack — `driver` (Karabiner) → `eventTap` (skhd, Keyboard Maestro, BetterTouchTool) → `system` → `globalHotKey` (Hammerspoon, Alfred) → `otherGlobal` → `menuItem` — and lower wins. `ShortcutLayer` reads the *tool*, not just the source, because all six config scanners share `BindingSource.configFile` and would otherwise be ranked next to a menu item. A finding names the two things that collide — menu-order overlap, a system shortcut shadowing a menu item, a tool shadowing a menu item or a system shortcut, system-vs-system, system-vs-tool, tool-vs-tool, or one tool binding the same chord twice — and the verdict is `.winner`, `.tied` or `.menuOrder`; where the honest answer is "same layer, registration order decides, and no file records it", it says that rather than guessing. **Settings → Conflicts** puts the config sources first, then the list with a type filter, a related-app filter, the scan timestamp, a manual rescan and **Test this combo** per row.
- **Third-party shortcut config files are scanned**, so a conflict list can say "⌘⇧4 will never reach Safari" instead of just "two things want ⌘⇧4": Karabiner-Elements (`karabiner.json`, complex modifications with a mandatory modifier), skhd (`skhdrc`), Keyboard Maestro (hot key triggers, inactive macros and groups skipped), BetterTouchTool (newest `btt_data_store.version_*`, opened read-only through SQLite), Hammerspoon (`hs.hotkey.bind` with literal arguments; a variable modifier table is dropped rather than half-resolved) and Alfred (workflow hotkeys, following `prefs.json` for synced preferences). On by default, switchable in **Settings → Conflicts**, scanned at launch and on demand but deliberately not on every app switch. Each parser is a pure function over text/data/plist so it is tested against fixtures.
- **Combo lookup.** Typing a combination into search (`cmd shift 4`, `⌘⇧4`, `opt cmd t`) answers *who owns this* or *it is free*, instead of returning an empty list that reads as "not scanned". A query is only a combo when every token is a modifier or a key, with exactly one key and at least one modifier — which is what keeps `cmd safari` a plain text search. It matches on the same chord key the conflict detector groups by, so the two can never disagree.
- **Live shortcut test.** **Test this combo** in the conflict list watches one real keypress: two listen-only event taps, one at the head of the chain and one at the tail, so a key that arrives at the head and never reaches the tail was swallowed by another app's tap — a fact, not an inference. Above the tap layer it falls back to what came to the front. `LiveTestVerdict` names one of six outcomes with an explicit tone (`confirmed` / `informative` / `inconclusive`) and states its own blind spot: past the tap layer a system shortcut can take a key without leaving a trace. While listening, the engine suspends every panel behaviour and all swallowing, so Kaname can never be the thing that ate the key.
- **The drag guide knows what went wrong.** Asking for Accessibility now floats a non-activating panel inside System Settings, under the list, carrying the Kaname icon so the drop adds *and* enables the entry in one gesture. The panel is a small state machine (`PermissionGuideState`) rather than a static hint: closing Settings moves it to the middle of the screen with **Open Settings**, and a cancelled password / Touch ID prompt says *cancelled — drag again*. The panel flies in from the Kaname window along an arc (`PermissionGuideFlight`) and is positioned on the Settings window's content area — sidebar width included — so it sits under the list rather than under the sidebar; a window too small to hold it keeps the old below-the-window placement. The icon carries a dashed ring and a bobbing up-arrow, both frozen under Reduce Motion. The permission row mirrors the panel: *waiting for authorization* while it is up, *continue* once it closed unfinished.

## Changed

- Shortcut data source: the primary source is the live menu bar of the frontmost app; the static list is a fallback.
- Bundle identifier changed from `com.suliveevil.kaname` to `com.suliveevil.kaname`.
- Minimum macOS version is 14.0 (Sonoma). The earlier project mixed 15.7 and 14 deployment targets; it now uses 14.0 consistently.
- The default sort order is **Smart order**; every other order is still available.
- Conflict detection also considers enabled macOS system shortcuts, and the conflict list shows where each clash comes from.
- The palette header carries an app selector and *Export Markdown*.
- The privacy text states the single manual network request (the update check); everything else remains local.
- **Rows show the complete shortcut.** The panel no longer renders only "the next key": each row lists the full combination, so the display is stable while modifiers are pressed and released.
- **Completing a shortcut lets it through.** Kaname highlights the completed row, closes the panel, and lets the key event continue to the front app unchanged; it never synthesizes keystrokes.
- **Panel and search are mutually exclusive.** Only one is visible at a time: opening search closes the panel and vice versa. The switch hotkey moves between them: search visible → panel, panel visible → search, neither → panel.
- **The swallow decision is a value type again.** "Should this keystroke be eaten?" was answered inside the 693-line class that owns the tap, its thread, its run loop and two timers, reading three parallel collections through a guard with a comment warning that one of them had to stay in it. It is `KeySwallowRules` in `Core/Pure` now — one value, three channels, eleven tests, including the Escape-only channel that guard existed to protect. `TapDiagnostics` does the same for the disable line that diagnosed five freezes: field order, `stood_ms=?` rather than a misleading zero, and a teardown form that does not say "torn down" twice.
- **Two copies of the key-event construction became one.** `keyDown` and `keyUp` repeated fourteen lines each, and had already drifted: only one carried the typed characters, only one read the autorepeat flag. Neither difference was a decision. `keyDown`/`keyUp` also no longer emit twice on the swallow path.
- **New default placement.** The panel covers the front window by default instead of sitting beside it; the old placement remains available as **Beside the front window**. `attachToFrontWindow` is replaced by the four-value panel placement setting.
- **Settings/statistics no longer use UserDefaults.** Both are plain JSON files in Application Support; the preference domain is read once for migration and is not written any more. Uninstalling or reinstalling the app no longer depends on the preference domain, so data survives unless the folder is deleted.
- **A held modifier narrows the panel.** Summoning by long-pressing ⌃/⌥/⌘ pushes that set onto the prefix, so the panel narrows which-key style; the hotkey and double-⌘ summon it with an empty prefix, where every row is a complete combination. The code comments and the documentation now say so instead of describing the opposite.
- **Esc closes the panel whatever the modifiers are**; ⌫ still backs out one chord stroke and is only handled with no other modifier held.
- **Switching apps or desktops closes the panel** rather than refreshing it in place; summon it again for the new app.
- **The app no longer treats its own activation as a frontmost-app change.** Activating for the search palette or Settings made Kaname the frontmost app, and the catalog was rescanned from its own (empty) menu bar — the panel fell back to the built-in catalog and the palette renamed itself "Kaname". A scan result from an older request can also no longer overwrite a newer one.
- **Settings and statistics are written once, after a pause, by one writer.** Settings changes coalesce (350 ms) and the write reads the snapshot at fire time; a press is recorded in memory and flushed 1.2 s later on a utility queue, then once more at quit. A failed write is logged instead of silently lost.
- **Key events are decoded lazily.** The tap reads the Unicode string only while a surface is taking keys or a binding is being recorded, and the panel's rows are cached until the prefix, catalog, chips, favourites-only toggle, ignored titles or page size changes.
- **The conflict list is typed rather than flat.** It used to print "%d chords are bound more than once" and a bullet per member, which invites the question *so which one fires?* and could not answer it. It now carries a type badge, the layer verdict, a per-member badge, the two filters and a **Test this combo** button, and it is built from a cache instead of rescanning every app each time the page opens.
- **Row interactions live in testable pure code**: `RowKeyRouter` (run before copy, one implementation for the panel and the palette), `PanelRowBuilder`, `HeaderLayout`, `PanelOrdering`, `PanelSections`, `PanelSelection`, `PanelKeyIntake`, `PendingModifiers`, `ChordComposition` and `PanelState`.

- **Rows read as two clusters, and a page fills down its columns.** The chord slot is sized by the chord style — 70 pt for symbol chords, 132 pt for the `words` style — instead of one 120/96 pt cap for both, the menu path is aligned to that slot's trailing edge, and the width this frees goes to the command name. At the default cover window (1470 pt, two columns) a chord used to sit 291 pt from its own menu path and 36 pt from the next column's command; it now sits about 110 pt from its path, on the other side of a hairline column rule. The page is filled **down** each column to the height the panel actually has instead of being divided evenly: three columns holding 50 rows used to show 17 · 17 · 16 and leave the card short of the window it covers, and they now fill the first columns to the measured capacity. `LazyVGrid` filled across as well, so a list ordered by the chord zig-zagged and ↓ moved sideways; both now follow the same order, down a column first.
- **Menus of data are not read as menus of commands.** A browser's *Bookmarks* and *History* menus list saved links and visited pages; Safari's tree reached 2500 of them, which is the scanner's cap, so *Window* and *Help* were never read at all. A top-level menu is now judged by its name (`Bookmarks`, `History`, `Reading List`, `Downloads`, in English and Chinese — the only two languages the app ships), keeping the commands that carry a shortcut and dropping the list; a nested submenu is judged by a sample of its children's shortcuts, so a day of history or a bookmark folder is skipped whole. Safari scans 179 items in 243 ms where it used to scan 2184 in 2263 ms (and 2500 at the cap before that); Chrome 159. The scan cache schema is bumped, so scans written by the old walk are dropped rather than shown.
- **New pure modules**: `MenuContentPolicy` (what a menu of data looks like) and `PanelColumnFill` (how a page fills its columns), with tests.
- **Asking for Accessibility no longer pre-registers the app.** `AXIsProcessTrustedWithOptions(prompt:)` added Kaname to the list **switched off** before the user had done anything, and that half-registered entry is what the drag instruction could not fix — dropping the icon in again is how the "already listed but the switch won't stick" support question happens. The guided flow now opens System Settings, raises it explicitly (a deep link does not bring a running Settings forward) and lets the drop add and enable the entry in one step; Input Monitoring keeps its system prompt, which does not have the same problem.

## Removed

- **The static list as the only source.** The 100-entry catalog became a fallback behind live menu scanning.
- **The fixed top-left overlay placement**, replaced by anchoring to the frontmost window.
- **The auto-hide delay / 自动关闭延时已移除。** The `autoHideDelay` setting and its model field are removed from the app, not hidden behind a default: no panel times out any more. A panel closes only when you press a complete shortcut, press Esc, or press the panel (or switch) hotkey again.
- **The "next key only" row label.** Rows render the complete combination.
- **The pinned/unpinned panel distinction**, including the separate auto-close rules for browse panels.
- **Both "Execute menu commands" switches.** `allowPanelExecute` and `allowSearchExecute` never controlled anything after rows started replaying their chord: the first had no callers, the second only switched one footer sentence — and it was wrong, telling users Return copies while Return ran. With them go `PanelState.allowsExecution`, `PanelState.appCanExecute`, `execute(rowID:)`, `HotkeySpec.isValid`, `.searchHint`, `.searchCopied` and `.browserExportDone`.
- **Dead state and dead keys.** `PanelState.highlightedRowIDs` had no readers, and `KeyToken("fdelete")` became a constant.
- **The browser window.** Its two jobs moved into the search palette (app scope and Markdown export), so the window, its key monitor and its refresh button are gone.
- **The review sort mode.** `RankMode.review` ordered the statistics page by "least recently used first" — a second, weaker way to ask the question `smart` already answers with decayed usefulness — so the mode, its menu entry, its two strings and its two tests are gone. A settings file that still says `"review"` decodes to `smart`: a throwing decode would take the whole document with it. The default mode keeps its behaviour and loses the vocabulary: it is now **Smart order** / **智能排序**.

## Fixed

- **The hand-over to the engine is bounded.** Moving the tap callback off the main thread left one `DispatchQueue.main.async` per event between the two, which is an unbounded queue: a main thread stuck for thirty seconds accumulated every keystroke typed during it and replayed the lot on recovery, opening and closing the panel for inputs the user could not see. `InputMailbox` caps the queue at 32 and delivers it as one batch on one hop. A drop is safe here because the buffer only carries the *panel's copy* — the event itself was already returned to the system on the tap thread — and the debt a drop leaves (a modifier the panel still believes is held) is paid with a single `.interruption` at the end of the next batch, which is the same event the engine already handles when the system disables the tap. Seven tests cover the bound, the reset, and the fact that a burst costs one hop rather than one per event.
- **The tap no longer depends on the main thread at all — the root refactor.** Four freezes on 2026-11-02, three of them ending in power-button resets, all shared one cause: the event-tap callback lived on the main run loop, so any main-thread wedge put the tap in front of a callback that could not run and froze every key and click in the session. The backoff (`TapHealth`) and the main-thread watchdog each held back one shape of that failure; the fourth episode proved the shape that remains — the tap was torn down after seven attempts, correctly, and the user still lost 83 seconds of input. The callback now runs on a dedicated thread with its own run loop, and nothing in the input path touches the main thread synchronously: the composed-stroke swallow decision reads a snapshot the engine publishes after every mutation (`ComposedSwallow.decide` + `ComposedSwallowState`, the old `shouldSwallowComposed` verbatim), and events reach the engine through an async hop that preserves order on the serial main queue. A wedged main thread can delay the panel by one hop; it can no longer delay the input stream. The watchdog now watches the tap thread instead of main, since that is the only thread left whose wedge could matter. Eight tests on the snapshot decision, including the honest worst case: a snapshot one event stale is wrong about one keystroke, never about the keyboard.
- **The freeze survived its own fix a second time — by going silent.** The backoff fix worked as designed: the third removal logged `attempt 1, 2, 3` with growing pauses. Then, after the third re-enable, the log went silent entirely — no disables, no scans — until the power-button reset. That silence is the structural blind spot: a disable notification is itself delivered *through* the tap callback, which lives on the main run loop, so a wedged main thread silences `TapHealth` precisely when it matters — tap enabled, callback unable to run, input stream frozen, nothing in the log. `MainThreadWatchdog` is the outside view: a background queue pings the main thread every 1.5 seconds, and two consecutive unanswered pings detach the tap from the input stream — a *disabled* tap is harmless, events go straight to the front app. When the main thread answers again the tap goes back. The trade is deliberate and stated: shortcuts go dark for as long as the wedge lasts, but the keyboard never does.
- **The backoff never engaged, and the freeze survived its own fix.** The first `TapHealth` reset its failure counter on *any* event getting through — "a tap that hiccuped once and then served a thousand keystrokes has earned a fresh start". Measured in the field, that assumption is wrong in exactly the situation it was built for: during a stall, events trickle through. Removing Kaname from Accessibility a second time produced eleven disables in two minutes, every one logged `attempt 1, trusted=true — re-enabling in 0.0s` — a mouse click between timeouts restarted the episode each time, so the pause schedule was never reached and the tap stayed installed in front of an input stream it could not serve until a second power-button reset. The load average through the whole episode was 4–10: the machine was not busy, it was *waiting*, which is the signature of a blocked tap and not of a resource shortage. Now an event only counts as proof of health once the tap has served for sixty seconds since the last disable; inside that window a passing event is what a dying tap still lets through, not evidence of life. The sixty-second mark is a boundary test, and the field episode itself is a regression test: disable, click at +5s, disable must be attempt 2, not 1.
- **A revoked permission could freeze the whole keyboard, and did.** Removing Kaname from the Accessibility list left the event tap installed and unanswerable, and the tap handler put it back on every notification, forever: `tapEnable` unconditionally, no trust check, no backoff. Each re-enable placed the tap back in front of the input stream, so every key and click waited out the tap's timeout first — input froze while `ps` showed 0% CPU, because blocking costs no CPU, which is why no resource monitor ever pointed at it. The diagnostics log recorded it plainly: twelve `event tap disabled by the system (timeout)` notifications in two episodes, zero on any other day, both episodes ending in a power-button reset. `TapHealth` is the policy and it says the opposite of what intuition suggests — a *disabled* tap is harmless (events go straight to the front app), so backing off is what restores responsiveness. The first disable is still re-enabled at once (one hiccup under load is normal), then the pause doubles to five seconds, and after six disables with nothing getting through the tap stops itself rather than shadowing input it cannot serve. A tap without the permission that created it is torn down on the first notification. Permission loss is now noticed while Kaname is in the background too: the undocumented `com.apple.accessibility.api` notification did not arrive on macOS 27, activation and wake refreshes miss the case where the user is in Settings, and `startPolling()` only runs while a permission is *missing* — so a five-second check of two local booleans closes the gap.
- **Dropping the guide's icon added nothing to the list.** Two separate faults, both in what the drag put on the pasteboard. First, `NSItemProvider(contentsOf:)` advertises `com.apple.application-bundle` for an `.app` and then fails to load it — a bundle is a directory, and it reads one as a file (`NSPOSIXErrorDomain 21`). Second, and the one that survived that fix: an item provider cannot write `NSFilenamesPboardType`, the legacy path-array flavour Finder writes with every file drag, and the privacy list reads it — so the pointer showed a **+** (a registered type matched) and the list still received nothing. The icon is now a real dragging session with the `URL` as its pasteboard writer (`AppIconDragSource`), matching LobeHub's `LobeGuideIconView`, including the three details that matter: `mouseDownCanMoveWindow` answering no (otherwise the press moves the panel instead of lifting the icon), the operation mask offering link and generic as well as copy, and the drag event rather than the mouse-down being handed to the session. Three tests hold the pasteboard contract, including one recording that an item provider cannot write the legacy flavour — so a future simplification back to `.onDrag` fails loudly.
- **The panel no longer says "cancelled".** macOS does not report why the prompt went away, and an authenticated drop whose payload could not be read ends in the same place; *not authorized yet* is true either way and still asks for the retry.

- **"You left this page" fired for everyone and blocked the drag.** It was derived from `CurrentExtensionURL` in Settings' preference domain, which is not the page Settings is showing: the value is a file path (`…/SecurityPrivacyExtension.appex`) rather than the identifier a deep link uses, and it does not change while Settings runs — with the app parked on Accessibility it still reported the software-update page from before. The phase also hid the drag icon, so the one action the panel exists to offer was gone. The phase, its two strings and its action are removed; `SettingsPaneProbe` keeps the sidebar width and records the measurement so the detector is not re-added. The remaining rule is the one that should have been there from the start: **a message may never take the drag icon away** — only "no Settings window to drop into" and "already granted" can.

- **System hotkeys say what they do.** Every row under *System hotkeys* read `⌘M … ⌘M`: macOS ships a `kHISymbolicHotKeyDescription` field that is empty for all 233 entries, so the reader had nothing to print and fell back to the chord itself. The names now come from `SystemHotkeyNames`, a table of the assignments a stock Mac registers (⌘Space → Spotlight, ⌃↑ → Mission Control, ⇧⌘3 → Screenshot, ⌥⌘⎋ → Force Quit, ⌘M → Minimize, …), answered in the interface language — 27 of the 79 entries this Mac reports were recognised. The rest — a chord you reassigned, or one of the slots macOS registers with nothing behind it (⌃F1, ⌃⌘D) — show **—** instead of the chord repeated as its own description, and a sequence that merely *starts* with a known chord is never given that chord's name. The middle column stays empty for these rows rather than printing the group title 79 times down the list.
- **Clicking away no longer clicks through.** Dismissing the panel by clicking outside it closed it *and* clicked whatever sat behind it in the app you were working in — moving the insertion point, changing the selection, pressing a button you never aimed at. That one press is swallowed now. Only presses that would land in the front app's window are: a click on the menu bar, the Dock, the desktop or another app's window is you reaching for something else, and eating it would make the panel feel like it had frozen the screen. Presses on the panel itself are the panel's, as before.
- **The pointer comes back.** Summoning the panel never moved the pointer, but leaving it did: clicking a row to run it, or clicking away to dismiss the panel, left the pointer wherever the panel sent it, and the place you were working in the app behind it was gone. The position is remembered when the panel opens and restored when it closes — by Esc, by running a command, by clicking away, by switching apps, all of them. If the pointer never moved (opened by hotkey, dismissed by Esc) nothing is warped, because moving it to where it already is only announces a jump. Opening the search palette from the panel keeps the pointer where it is; that surface is about to want it.
- **Tapping a modifier ticks it.** Only *holding* a modifier narrowed the list, so the Emacs spelling — ⌥, ⌘, C, one key at a time — never worked; releasing the key put the full list back. A press-and-release inside 0.35 s, with nothing typed while it was down, now leaves the modifier ticked, and each further tap narrows on top of the last. Holding still narrows temporarily: holding is looking, tapping is composing. A modifier that was used *with* a key (the ⌘ of ⌘C) is not a tap, and neither is the one still down when the panel opens — that one is the trigger.
- **⌫ undoes the tick you made last.** It removed whichever modifier came last in ⌃⌥⇧⌘ order instead of the most recently ticked one, so ticking ⌘ then ⌥ and pressing ⌫ dropped the wrong one. The ticks keep their order now. Nothing else changes: with no tick left, ⌫ still goes up one level of a chord, and the panel stays open either way.
- **The menu bar icon is visible on a dark menu bar.** `Image(nsImage:)` does not inherit `NSImage.isTemplate`, so the glyph was drawn in its own colour — black — and vanished into a dark menu bar. It is explicitly marked as a template now.
- **Escape closes the panel again** — on the built-in key and on a Caps Lock remapped to Escape by Karabiner. Escape, Tab, Return and Delete each carry a control character (`U+001B`, `U+0009`, `U+000D`, `U+007F`), and the key mapper preferred the character over the virtual key code, so Escape resolved to `U+001B` and was never equal to `esc`; the tap swallowed the press and nothing happened. Tab and Return had the same bug from the other direction — both resolved to `space`. Control characters now fall through to the key code, and the panel recognises Escape by key code, which is also how the tap claims it.
- **⌫ undoes a tick and pops a level again.** Its token is `delete`, which never matched while the key was resolving to `U+007F`, so the key had been inert since it was written.
- **The panel no longer changes height while you narrow the list.** Holding a modifier removes rows, and the window was sized from the rows on screen, so it shrank on every press and grew back on release. It is sized from the session's widest list now.
- **The panel title is no longer a close button.** Clicking the app icon or the app name dismissed the surface silently; the identity block is static now and closing has its own button.
- **Dimmed rows no longer show a selection marker.** They carry `index == -1`, which is also the "nothing selected" sentinel, so `selectionIndex == row.index` lit up every dimmed row whenever nothing was selected.
- **Rows no longer shift when hovered.** The marker and the pin star were inserted into the row's stack, pushing the title and keycap sideways as the pointer moved; both now sit in reserved space.
- **The pin star can no longer fire the shortcut.** A star click inside a row with a tap gesture could also run the row and inject its chord; it is a bounded child gesture now.
- **Pager buttons are clickable** (22 × 22 instead of the glyph's own ~10 pt), and decorative strokes are explicitly out of the click path.
- **The inline filter clears in the snapshot too.** Leaving the filter left `isFiltering`/`filterText` set, so the UI kept drawing a filter bar for a filter that was no longer active.
- **The search palette no longer swallows ⌃⌥P or ⌃⌘P.** It passed a hard-coded ⌃ to the navigation matcher, so any combination containing ⌃ plus P/N was treated as navigation and consumed.
- **Held keys no longer leak or repeat.** Repeats of a key the panel consumes are consumed too, running a row no longer repeats while the key is held, and ⌘⌫ / ⌥⌫ are consumed while the inline filter is open instead of deleting in two places.
- **Settings no longer lose a change to a concurrent write** (two writers within the debounce window used to be last-wins).
- **The panel highlights the rows on the page.** `highlightedIDs(for:)` discarded its page argument and recomputed the same prefix over the whole catalog.

- **The palette's scrollbar no longer follows the pointer.** Hovering a row selects it — Return has to act on the row under the pointer — and every selection change scrolled that row to the centre of the list, so moving the mouse over the results dragged the scrollbar with it. The palette now scrolls only when it asks to: the keyboard moving the selection, a new query, or opening the palette.
- **The panel says what it means and is legible.** The menu path (the only answer to *where does this command live*) measured 2.84:1 and the footer's key hint (*the only place the panel teaches its own keys*) 2.49:1, both on 10.5–11 pt text; both move to secondary text, as do the palette footer and the section counts. A dash no longer stands for both "this hotkey has no name" and "this command has no shortcut": a nameless system hotkey is named by its chord, a command without one says **No shortcut**, and a built-in row's owner reads **Built-in** instead of a dash. Counts carry a unit — the title bar's bare `136` next to a warning triangle read as "136 conflicts", while *Settings → Conflicts* said 42; it now reads `136 items`. The title bar's glyph-only buttons get accessibility labels, 28 pt hit areas and a hover fill that can be seen (6 % white was invisible); the conflict triangle was the loudest mark in that row and could not be clicked, so it is quieter and labelled. The footer no longer repeats the app name the title bar already shows, and its hint no longer duplicates the header's with a different inflection.
- **Smaller fixes.** The two permission grants use one accent instead of blue and orange. The executed HUD caps at 460 pt and truncates, instead of stretching across the screen for a long command name. Statistics read `81 presses 13 shortcuts` with correct singulars, where two bare numbers used to sit side by side and every one-shortcut app said "1 shortcuts". *General*'s first group has a heading like every other group on that page.

## Upgrade notes

- **Accessibility must be granted once.** If the bundle identifier or the code signature changed — a local or ad-hoc rebuild, or an install over a release signed by another identity — macOS sees a new app: open **System Settings → Privacy & Security → Accessibility**, remove the stale Kaname entry if present, and enable the new app. Grant Input Monitoring too only if the panel does not appear after that. See [docs/en/PERMISSIONS.md](docs/en/PERMISSIONS.md).
- **macOS 14.0 is required.** The app does not run on macOS 13 or earlier.
- **The panel does not close by itself.** If you expected it to disappear after a few seconds, press Esc (or complete a shortcut). There is no auto-hide setting to configure.
- **The trigger is not a prefix in the hotkey and double-⌘ paths.** The panel lists the app's full shortcut set and highlights the rows that start with the modifiers you hold; summoning by a long modifier press seeds that set as a prefix instead. To run a row with the keyboard, use ↑/↓ and Return, or type the complete shortcut.
- **The default placement is Cover the front window.** Pick **Beside the front window** in **Settings → Appearance** to restore the old behaviour, or choose a fixed size or full screen.
- **Settings and statistics move on first launch.** Kaname reads `settings.json`/`usage.json` if present, otherwise migrates the previous `settings.v2`/`usage.v2` UserDefaults payloads, otherwise the older `com.suliveevil.kaname` domain. The old defaults are left in place and can be deleted with `defaults delete com.suliveevil.kaname` and `defaults delete com.suliveevil.kaname`.
- **Statistics are grouped by app.** Existing `bundleID|chord` keys are reused, so history carries over; the Statistics tab lists presses per app, and system/built-in shortcuts appear as **System / built-in**.
- **Hyper keys need no extra setup.** Record a three-modifier hotkey as usual; a tool that adds a fourth modifier still matches it.
- **Replacing an existing install with an ad-hoc signed local build invalidates the privacy grant** because the signature changes; remove the old Accessibility entry and re-add the new app. The same applies when replacing one build with another signed by a different identity.
- The app remains sandbox-free and is not distributed through the Mac App Store.
