# 发布说明

[English](../en/RELEASES.md) · [中文](RELEASES.md)


Kaname 通过辅助功能读取前台 App 的菜单栏，在一个浮层里显示它的快捷键，也能替你执行。这份说明记录 App 做什么、一路上改了什么，以及升级时该做什么。

## 亮点

- **实时菜单扫描** —— 任何有标准菜单栏的 App 都能用，包括菜单分组、快捷键与启用状态。另有一份约 100 条的内置目录作为兜底。
- **which-key 式收窄** —— 面板打开时按下的修饰键会加入筛选，所以按住 ⌘ 会显示 ⌘ 集合与下一键的行（C、⇧S……）。唤出那一次按下是触发器而不是筛选 token：热键（⌃⌥⌘K）与连按两次都从完整列表打开，每行都是完整组合键。面板打开期间修饰键变化会实时收窄或放宽，全部松开又恢复——无论哪种，面板都保持打开。只按住 ⇧ 不会收窄，所以列表永不为空。
- **多段组合键** —— ⌘K ⌘C 这类多击快捷键逐层下降。⌫ 回退、Esc 关闭、面包屑显示你在哪一层。
- **面板等你** —— 触发键不是前缀：面板一直留到你完成一个快捷键——它会被高亮，然后传给 App——或按下 Esc。没有可配置的自动关闭延时。
- **每行显示完整快捷键**，按菜单分组、自动分页，带冲突标记与灰显的不可用项。
- **可操作的面板** —— ↑/↓ 选择、←/→ 翻页、执行键执行、Esc 关闭。面板打开时这些键由面板消费；点击某一行同样有效，还有后续步骤的行会打开下一层。两个行操作键都是录制的绑定：执行键（Space）关闭面板并执行该行的菜单项，复制键（Return）只把组合键写进剪贴板。页脚提示会渲染你实际选的键。
- **渐进高亮** —— 按住 ⌘ 会点亮每一行以 ⌘ 开头的行；再加 ⇧ 收窄这片光；完成一个快捷键时它的说明会亮一下，随后面板关闭。行选中（↑↓）是另一种独立视觉状态。
- **搜索面板** —— ⌃⌥⌘F，对范围内 App 的菜单快捷键与内置目录做模糊搜索。空格分词、顺序无关（`com op x` = `op cm x` = ⌘⌥X），`+` 作分隔符，修饰键别名（com/cmd、op/opt/alt、ct/ctl、sh/sft 及其符号），中文标题支持全拼与拼音首字母（`jq` → 剪切），以及英文单词首字母（`fs` → Find Similar）。Return 执行选中的命令。
- **搜索面板还承载 App 范围与导出** —— 它的 App 菜单能扫描任何运行中的 App，不只是前台那个（实时面板仍跟随真正在前台的那个），Markdown 导出通过存储面板保存你正在看的那张表：按菜单分组，列为 `Shortcut` / `Action`，不可用项会标注。
- **Hyper 键可用** —— 三个及以上修饰键的热键接受修饰键的超集，所以 Karabiner 风格的 hyper（⌃⌥⇧⌘）+ K/F 能正确触发面板与搜索。
- **面板位置可选** —— 覆盖前台窗口（默认，屏幕居中且保证两个方向都大于该窗口）、固定尺寸且可编辑宽高、铺满屏幕，或旧的"窗口旁边"。
- **系统热键冲突** —— Kaname 读取 macOS 符号热键（聚焦搜索、调度中心、窗口平铺……），并标出与前台 App 菜单快捷键相撞的那些。系统快捷键只读：不绑定、不修改、不重映射任何东西。
- **放得下的标题栏** —— 按面板宽度量三种密度，所以设置与关闭按钮在单列面板里仍然够得着，而不会被挤到面板外面。
- **排序** —— 统计页是一张扁平列表，快捷键在前，**排序依据**可选**快捷键**（默认，沿用面板的键盘顺序）、**App** 或**功能描述**。
- **按 App 统计、持久存储** —— 设置与统计以原子写入的 JSON 文件存在 `~/Library/Application Support/Kaname/`，损坏文件会保留以便检查。统计是每条使用键一行、带一个排序字段，重装 App 不再有丢数据的风险。
- **权限帮助** —— 一个专门的窗口，每个权限一张卡：它用来做什么、必需/可选、实时状态，以及一个既触发系统提示**又**打开对应系统设置页的授权按钮。轮询会把卡片翻成绿色的"权限已授予"并把窗口带到前面；Kaname 图标也可以直接拖进辅助功能列表。
- **独立的"关于"页** —— 版本、构建号、系统、检查更新、数据目录、仓库与协议。
- **可以附进 bug 报告的诊断** —— **设置 → 通用 → 诊断** 里有两个导出。**导出诊断报告…** 写一份 JSON：权限、监听状态、扫描结果、你的设置，以及打印对应日志行的命令。**导出诊断包…** 把日志打包。`KANAME_SELFTEST=1` 会写出同一份报告，App 正在运行时也能用。
- **同时只有一个面板** —— 打开搜索会关闭面板，反之亦然；一个全局热键（默认 ⌃⌥⌘S）在两者之间切换。
- **手动检查更新** —— 关于页可以向 GitHub releases API 询问最新版本。不下载、不安装，也不轮询。
- **中文 / English 界面**，支持降低透明度与增强对比度，定位会感知前台窗口并避开当前焦点元素。
- **工程实践** —— 无 AppKit 依赖的核放在带单元测试的 Swift Package 里，GitHub Actions、共享 scheme、发布/安装脚本、文档与截图。

## 值得知道的修复

- Esc 无论带不带修饰键都会关闭面板。⌫ 仍然回退一段组合键，且只在没有按住其他修饰键时生效，所以 ⌘⌫ 仍是普通快捷键。
- 切到另一个 App 或另一个空间会关闭面板；为新 App 重新唤出即可。
- **Kaname 不再把自己当成前台 App。** 打开搜索面板或设置会激活本 App，目录于是从它自己的菜单栏被重新扫描——面板退回内置目录，搜索面板把自己改名成"Kaname"。
- 浏览时不注入任何东西；执行一行时按压菜单项本身，只有按压不可用时才回放那一条组合键。
- 行操作键是录制的绑定——Space 执行、Return 复制——所以你手工录的那一对会覆盖两个默认值。
- 废弃的设置项被丢弃而不是被带着走：已有的设置文件仍能解码，键会在下一次保存时消失。

## 安装

要求：Apple Silicon（arm64）上的 macOS 14.0 Sonoma 或更高版本。Bundle identifier 是
`com.suliveevil.kaname`。发布的 DMG 是 universal 二进制（x86_64 + arm64），但 Intel 不在支持或测试范围内：cask 刻意在安装阶段拒绝 Intel Mac，而不是把一个没测过的 App 发出去。

从 tap 安装：

```sh
brew tap suliveevil/tap
brew install --cask kaname
```

或从发布资产下载 DMG。从源码构建：

```sh
git clone https://github.com/suliveevil/kaname.git
cd Kaname
./scripts/install.sh
```

> 在没有 Developer ID 证书的机器上构建出的版本**未公证**，所以首次启动 Gatekeeper 会警告。Homebrew 默认对 cask 下载加隔离属性。要么在系统设置 → 隐私与安全性里点一次**仍要打开**，要么对已安装的副本执行 `xattr -dr com.apple.quarantine /Applications/Kaname.app` 去掉该属性。Homebrew 7 移除了 `--no-quarantine`，所以那个标志已不可用；每次 `brew upgrade` 后属性都会回来。

无论哪种方式，App 首次启动都需要**辅助功能**（系统设置 → 隐私与安全性 → 辅助功能）。只有在按键事件收不到时才需要输入监控。

## 升级说明

- **触发键若在 Karabiner-Elements 里被重映射，那条规则需要一个条件。** Karabiner 在 Kaname 的事件 tap 之下应用规则，所以作用在触发键上的规则（例如带 `to_if_alone` 的 `left_command`）在面板打开时照样触发，面板只看到规则的输出。自 2.3.1 起，Kaname 会通过**设置 → 触发 → 面板打开时通知 Karabiner**（默认开启）写入 Karabiner 的 `kaname_panel` 变量；给那条规则加上 `conditions: [{"type": "variable_unless", "name": "kaname_panel", "value": 1}]`，它就只在面板关闭时生效。不加这个条件，该设置不产生任何效果；没装 Karabiner 的机器则从不会发生写入。`variable_if` 是反向语义，会让规则在面板打开期间*保持生效*。
- **代码签名或 bundle identifier 变了，就要重新授予辅助功能。** 由另一个身份签名、或 ad-hoc 本地重建的版本，对 macOS 而言都是新 App：在隐私与安全性里删掉过期的 Kaname 条目，再启用新的那个。两者都没变的签名更新会保留授权。
- **Homebrew 升级是原地替换 App。** 先退出 Kaname（运行中执行 `brew upgrade --cask kaname` 会让旧进程继续持有已删除的二进制与事件 tap）。只有 bundle identifier 与签名身份都不变，辅助功能授权才会保留。每次升级都会被重新加隔离属性，所以新副本首次启动时要再批准一次（或去掉属性）。
- **卸载删的是 App，不是数据。** `brew uninstall --cask kaname` 会留下 `~/Library/Application Support/Kaname`（设置、统计、日志、本地备份）、偏好 plist、缓存与保存状态。`brew uninstall --cask --zap kaname` 会把它们全删掉，包括备份。两种方式都不清除辅助功能授权；用 `tccutil reset Accessibility com.suliveevil.kaname`，并在系统设置 → 通用 → 登录项里移除残留的登录项。
- **设置与统计移到 Application Support。** 首次启动时若 JSON 文件已在就读它，否则迁移之前的 UserDefaults 数据，因此不需要重新输入。旧的 defaults 留在原处，可用 `defaults delete com.suliveevil.kaname` 删除。
- **默认位置是"覆盖前台窗口"。** 更喜欢旧布局的话，在设置 → 外观里切回"窗口旁边"。
- **按住修饰键不再收窄面板，除非你就是这样唤出的**，而且面板从不自行关闭：完成一个快捷键会把按键交给 App，Esc 才是关闭方式。
- **按住修饰键唤出面板会收窄它**；松开又会放宽。
- 第三个热键（⌃⌥⌘S）在面板与搜索之间切换。
- 设置、按 App 的统计与数据目录原样沿用。
