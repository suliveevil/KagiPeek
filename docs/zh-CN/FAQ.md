# 常见问题

[English](../en/FAQ.md) · [中文](FAQ.md)


首次启动之后会遇到的疑问，答案都在这里。安装与权限见 [README](../../README.zh-CN.md) 与 [PERMISSIONS.md](PERMISSIONS.md)；内部实现见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 按住修饰键没反应

按顺序过一遍：

1. **Kaname 在跑吗？** 它是菜单栏 App，没有 Dock 图标。在菜单栏里找那个键盘图标。
2. **触发开了吗？** 打开 **设置 → 触发**。那里有两个独立开关：**修饰键手势**与**全局快捷键**。至少打开一个。两个都关就等于没有触发。
3. **辅助功能授权了吗？** 打开 **设置 → 权限**。读取菜单与创建按键 tap 都需要辅助功能。如果按键仍然收不到，再授予**输入监控**作为兜底并重启 Kaname。
4. **你在密码框里吗？** 安全输入会按设计隐藏面板。点进一个普通窗口再试。
5. **这个 App 有菜单栏吗？** 部分游戏、浮层与自绘 App 没有。辅助功能已授权但没有菜单栏时，Kaname 退回内置目录；如果目录被关掉，你就什么都看不到。
6. **按住够久吗，触发键是你以为的那个吗？** 默认停顿 0.5 秒（0.3–0.9 秒）。默认触发键是**右 Command**；你按左那个时，手势是刻意不触发的。
7. **有别的 App 抢了这个热键吗？** 如果用全局快捷键触发，检查是否与别的启动器或自动化工具冲突。三个及以上修饰键的热键在 Hyper 类工具额外加一个修饰键时也会匹配，这一点同样要查。

如果菜单栏图标整个不见了，退出任何重复的副本，再从 `/Applications` 重新启动 Kaname。

## 为什么某个 App 显示不出快捷键？

Kaname 通过辅助功能读取 App 的**菜单栏**。它只能显示 App 在菜单里真正声明为快捷键的东西。

- 直接实现在自绘视图、工具栏、网页内容或游戏里的快捷键，对辅助功能不可见，因此对 Kaname 也不可见。
- 有些 App 延迟构建菜单。先把该 App 的菜单栏打开一次，再触发 Kaname；切换 App 会强制重新扫描，按 App 的缓存只保留 20 秒。
- 有些菜单项刻意没有快捷键。Kaname 不会去猜。
- 如果该 App 的菜单栏异常庞大或缓慢，0.35 秒的 AX 超时可能把扫描截断。等 App 恢复响应后重试。

内置目录（约 100 条系统、文本编辑、Finder 与截图快捷键）能补上常见情况，但不可能知道某个 App 的私有快捷键。

## 明明 Kaname 在跑，为什么面板是空的？

空面板总会说明自己处于四种状态中的哪一种，优先级如下：

1. **缺少辅助功能** —— 这个状态压过其它一切，因为没有它任何扫描都完不成。面板会给出**权限引导**按钮，那是出路。
2. **仍在扫描** —— 一个转圈，不是结论。等扫描完成（大菜单要一会儿）。
3. **只看收藏但没收藏任何东西** —— 关掉这个筛选，或用星标收藏一项。
4. **没有匹配** —— 当前前缀、搜索词或筛选把每个菜单项都排除了。

如果显示的是权限那条，授予辅助功能后重新打开面板；见 [PERMISSIONS.md](PERMISSIONS.md)。

## 能不能不切过去就浏览另一个 App 的快捷键？

能。搜索面板的 App 菜单列出前台 App 加上所有运行中的常规 App。选一个，面板就会扫描并搜索那个 App 的菜单快捷键；标题处随之显示那个 App 的名字，Return 会在它里面执行菜单项。

浮层面板刻意分开：无论窗口在浏览哪个 App，面板始终跟随真正的前台 App，因为你的按键只会到达那个 App。

## 怎么导出一张快捷键表？

在搜索面板里按导出按钮并选位置。Kaname 写出一个以当前范围 App 命名的 Markdown 文件，每个菜单一节，每节一张 `Shortcut` / `Action` 表。不可用项标为 `(unavailable)`，这张表反映屏幕上的匹配结果——输入框为空时就是整张列表。

## 为什么是两个权限而不是一个？

**辅助功能是必需的，输入监控是可选的兜底。**

- **辅助功能**让 Kaname 读取其它 App 的菜单栏、创建全局按键 tap，以及（在你允许时）通过 `AXPress` 按压菜单项。没有它，只能显示内置目录，任何触发都不会发生。
- **输入监控**覆盖"macOS 不把按键事件投递给仅靠辅助功能创建的 tap"这类情况。多数 Mac 上你从不需要它；Kaname 单独检测它，只在你确实收不到按键时才指向它。

起步不需要两个都授权。先授辅助功能，试着按住 ⌘，只有面板不出现时才加输入监控。完整走查见 [PERMISSIONS.md](PERMISSIONS.md)。

**设置 → 权限**里的**请求授权**会打开对应的系统设置页（辅助功能或输入监控），你不必自己去找。只有输入监控会同时弹出系统授权提示：对辅助功能来说，弹提示只会把 App 预先注册进列表却不启用，所以那一条要靠把 Kaname 图标拖进列表。

## 怎么把 Kaname 拖进权限列表？

权限页显示一个 Kaname 的 App 图标，它是真正的拖拽源。把它拖进 **系统设置 → 隐私与安全性 → 辅助功能**（或**输入监控**）的列表里，就把正在运行的 App 加进去了：先打开那一页，再把图标放到列表上。当 Kaname 根本没出现在列表里时，这是最快的修法。之后你还得把该条目打开——在你拨动开关之前，macOS 什么都不授予。

## Kaname 会记录我输入的内容吗？

不会。没有按键日志，也不抓取文字。快捷键处理全在本地；唯一的网络请求是下文所说的手动检查更新。

- 全局按键 tap 用于计算修饰键/按键状态并识别录制的热键。事件原样传给前台 App，只有 Kaname 自己的面板、搜索、切换热键与面板的导航键会被消费；完成一个菜单项的快捷键**不会**被消费。任何事件都不记录、不回放、不落盘。
- 使用统计只存**每条 `bundleID|chord` 的次数与最近使用时间**，不是一串按压记录。它们存在 Application Support 下的 `usage.json`，在设置里按 App 与快捷键各一行显示，可以重置。
- 菜单扫描按 App 缓存在内存里 20 秒。切换 App 会强制重扫，App 启动/退出会清缓存，改变语言或目录设置也会刷新。它们不上传、不归档。
- 搜索查询不记录。
- **检查更新是唯一的网络请求。** 只在你按下**检查更新**时运行，读取公开的 GitHub release 文档，不发送任何关于你、你的 App 或你的快捷键的信息。
- macOS 报告安全输入（密码框、登录窗口）时，面板会隐藏。

Kaname 没有账号、遥测或崩溃上报端点。见 [README](../../README.zh-CN.md#隐私) 的隐私一节。

## 为什么 Kaname 不上架 Mac App Store？

因为 App Sandbox 让核心功能无法实现。Kaname 必须通过辅助功能 API 读取其它 App 的菜单栏、用事件 tap 观察全局按键；这两件事都在沙盒 App 的权限之外。所以本项目以 Developer ID/公证（本地构建则 ad-hoc）的形式、在沙盒关闭的前提下于商店之外分发。

这个 App 也是 GPL-2.0 许可的。App Store 分发会附加与许可证冲突的额外条款。

## 搜索是怎么工作的？

按 **⌃⌥⌘F**（默认）打开搜索面板，或在面板打开时按 `/`。它在范围内 App 的菜单快捷键上搜索（未选范围时再加上系统热键），匹配标题、组合键、菜单路径、修饰键名与拼音。

- **词项无序，且必须全部命中。** `com op x`、`op cm x`、`cmd+opt+x` 都能找到 ⌘⌥X；`+` 只是另一种分隔符。
- **认识修饰键别名**：`com`/`cmd`/`command`/`cm`/`⌘`、`op`/`opt`/`option`/`alt`/`⌥`、`ct`/`ctl`/`ctrl`/`control`/`⌃`、`sh`/`sft`/`shift`/`⇧`。
- **中文标题匹配拼音**：全拼（`jian qie`）、带空格的分音节，以及首字母（`jq` 匹配剪切）。
- **英文标题匹配单词首字母**：`fs` 找到 Find Similar。
- 匹配更好的排在前面；排序不受你输入词项顺序的影响。
- **↑/↓** 移动选中项。
- **Return 执行选中的菜单项。** 搜索面板关闭，你选定范围的 App 被激活，菜单项在那里被触发：扫描留下了菜单项时就在菜单里按压它，只有找不到可按压元素时才回放它的组合键。这不是复制：搜索面板根本没有复制动作。
- 要复制组合键而不执行，用面板里的复制键——默认 Return，是一个录制的绑定。
- 菜单项可能有破坏性（删除、清空废纸篓、退出），所以在你按 Return 之前什么都不运行；第一个匹配只是被选中。

## 快捷键旁边的 ⚠︎ 是什么意思？

另一条绑定占用了同一组合键。Kaname 在 **设置 → 冲突** 里列出每一处冲突，附带类型——菜单顺序重叠、系统快捷键压住菜单项、工具压住菜单项、工具与自身重叠、系统对系统、系统对工具、工具对工具——以及可能的胜者。与已启用 macOS 系统快捷键的冲突也在其中，并标为系统层。

这个警告只是信息。真正决定哪个菜单项拿到该快捷键的是 macOS，Kaname 改不了。冲突往往意味着某个 App 在不同菜单里重复暴露了同一个快捷键，或某个全局快捷键撞上了 App 的菜单快捷键。如果 App 自己的行为让你意外，冲突列表就是该看的地方。

## 为什么 macOS 系统快捷键会显示成冲突？

macOS 自己有一套全系统快捷键（聚焦搜索、调度中心、截图、切换输入源……）。Kaname 通过 Carbon 读取已启用的那些，与 App 的菜单快捷键比对。撞上时两边都标 ⚠︎，冲突列表在**系统热键** / **System hotkeys** 下显示系统那一条。

那个列表是只读的。Kaname 从不绑定、修改或禁用系统快捷键；要改请去 **系统设置 → 键盘 → 键盘快捷键**。

## 为什么有些系统快捷键显示成组合键而不是名字？

macOS 不公开自己热键的名字；描述字段永远是空的。Kaname 内置一张标准 Mac 自带分配的对照表，所以常见的会读成**聚焦搜索**、**截图**、**调度中心**。表外的组合键——你重新分配过的，或某个已启用但背后没有功能的槽位——就把组合键本身当行标题，快捷键列留空。

## 为什么来自 Karabiner、skhd 或其它配置工具的快捷键不能执行？

那些工具在自己的键盘层里实现快捷键，位于菜单栏之下。Kaname 读取它们的配置文件以提示冲突，那些行可以出现在面板与搜索里——见下一个问题——但它们**只展示、从不执行**：点击只会复制快捷键，右键菜单也是这么说的。回放一次按键反正也到不了那个工具所在的层，猜着回放还可能触发错误的动作。这类快捷键请在工具本身里绑定。

## 为什么面板里看不到 Karabiner、skhd 或 Alfred 的行？

把它们显示出来是另一个开关，**默认关闭**，位置在 **设置 → 冲突 → 配置文件 → 在面板与搜索里显示配置工具**。一张菜单快捷键速查表应当在 App 自己的命令上打开，而不是躲在六张工具卡后面。关掉它不会停止扫描，也不会清空冲突列表：两个开关互相独立，冲突页在两种情况下都照常工作。显示时每张工具卡各自记住自己的折叠状态；有筛选条件时所有卡自动展开，匹配的行永远不会被折叠挡住。

## 触发键在 Karabiner 里被重映射后，为什么面板打开时 ⌘ 不起作用？

因为 Karabiner 在 Kaname *下方*改写键盘。它在驱动层拿走物理按键、应用规则、再通过自己的虚拟键盘发出结果；Kaname 的事件 tap 位于其上方，只能看到 Karabiner 产出的东西。绑定在同一个键上的规则——`left_command` 配 `to_if_alone` 是最常见的形状——因此在面板打开时照样触发，单独一个 ⌘ 变成那条规则的快捷键（⌘/ 切换输入法）而不是一次修饰键按下，于是它永远不会加入筛选。

Kaname 看不穿 Karabiner，而吞掉被改写的事件只会让前台 App 也看不到它。它能做的是在 Karabiner 唯一会从外部读取的通道上——一个变量——告诉对方面板开着。

1. **设置 → 触发 → 面板打开时通知 Karabiner**（默认开启）。面板显示期间 Kaname 写入 `kaname_panel=1`；关闭时写入 `0`；启动与退出时也写 `0`，所以崩溃或强制退出不会把这条规则永久压在关闭状态。
2. 给作用在那个键上的规则加一个条件，**让规则只在面板关闭时生效**：

```json
"conditions": [{"type": "variable_unless", "name": "kaname_panel", "value": 1}]
```

它是 `from`/`to` 的同级字段，完整的一条规则长这样：

```json
{
  "description": "Command to Cmd+Slash (click) for toggle Input Method",
  "manipulators": [
    {
      "type": "basic",
      "from": {"key_code": "left_command", "modifiers": {"optional": ["any"]}},
      "to": [{"key_code": "left_command"}],
      "to_if_alone": [{"key_code": "slash", "modifiers": ["left_command"]}],
      "conditions": [{"type": "variable_unless", "name": "kaname_panel", "value": 1}]
    }
  ]
}
```

`variable_if` 是反向语义，会让规则恰好在面板打开期间*保持生效*，所以要用 `variable_unless`。保存后 Karabiner 会重新加载 `karabiner.json`，变量是实时的——两个 App 都不需要重启。不加条件的规则行为与从前完全一致，没装 Karabiner 的机器永远不会发生写入：找不到它的 CLI 时这个开关什么都不做。

## 为什么 Kaname 不执行睡眠、重启、关机、锁屏、退出登录或强制退出？

因为这六个动作会动整台 Mac，而这里一次误按 Enter 是不可恢复的。睡眠（⌥⌘Power）、重启（⌃⌘Power）、关机（⌃⌥⌘Power）、锁屏（⌃⌘Q）、退出登录与强制退出登录（⇧⌘Q、⌥⇧⌘Q）以及强制退出（⌥⌘Esc）都标成红色，Kaname 永不执行：点击会说明原因，复制键会复制快捷键，右键菜单只提供两个复制动作。判定按组合键而不是本地化标题，并且同时作用于 App 菜单区与系统区。⌘Q **不受**限制：它退出当前 App，整台 Mac 照常运行。

## 按了 ⌘K 之后面板为什么不关？

因为 `⌘K` 是**多段组合键**（chord）的第一段，例如 VS Code 类编辑器里的 `⌘K ⌘C`。当前这一段还有后续可接时，面板下降一层并显示可以接着按什么；面包屑显示当前前缀。

- 按下一段继续。
- 按 **⌫** 撤回你最后加的东西：如果最后加的是筛选字母就删那个字母，否则移除那个修饰键；筛选清空后再往回退一层。它只在没有按住其它修饰键时生效，所以 ⌘⌫ 仍是普通快捷键。**Esc** 关闭面板。
- 按完成该快捷键的那个键收尾：面板高亮该菜单项约 0.4 秒、关闭，快捷键在前台 App 里运行。没有匹配的键会让面板保持打开——它不再因为没命中就关闭。

除此之外，只要面板背后的 App 还握着焦点，面板就保持打开——这是刻意的持久设计。松开修饰键不会关掉它，也不会清空筛选。

如果某条多段组合键看不到，可能是该 App 没把它暴露成菜单快捷键，或扫描漏掉了那个菜单。

## 面板什么时候会关闭？

v2.1.0 把面板做成了**持久面板**：自动关闭延时及其设置被删除，现在仍然没有空闲计时器、没有"浏览"与"固定"两种模式，也没有可配置的超时，你可以按自己的节奏读。变化在于：**持久只针对打开它的那个 App**。

- 那个 App **失去焦点**（切换桌面、切到全屏 App、Mission Control，或激活了别的 App），面板立即关闭；
- 切换前台 App 或活动 Space 同样关闭面板，并且只刷新一次菜单扫描；
- 你按下**完整快捷键**——面板高亮它约 0.4 秒后关闭；
- 你按 **Esc**；
- 你再次按**面板热键**（或**面板/搜索切换**热键）。

松开你正按着的修饰键不会关，也不会清空筛选。如果某次切换的焦点通知没送达、旧面板残留在新 Space 上，下一次触发键会在同一次手势里先关掉它再打开新面板——不需要按两次。依旧没有计时器：结束一次面板会话的是焦点变化，不是时间。

## 为什么 Esc 能关面板，而点外面不行？

Esc 是面板明确的"关闭"手势。它在任何其它判断之前先按键码匹配，所以带不带修饰键都有效：⌥⌘Esc 同样关闭面板，而且那一次按键永远不会到达前台 App。点击面板外部不算关闭，因为面板是非激活的：别处的点击照常送给前台 App，所以不能指望外部点击关掉它。Esc 加上面板/切换热键，就是可预测的两条出路。

## 为什么我按的快捷键还会到达 App？

因为 Kaname 只**观察**按键，不重映射也不回放。你按下完整快捷键时，Kaname 用这个事件去高亮匹配的菜单项、关闭面板，并让同一个事件继续送往最前台 App。所以菜单项会立刻运行，就像面板从未打开过。Kaname 真正消费的只有它自己的热键与面板的导航键（方向键、Space/Return、Esc）；完成的快捷键永远不会被吞掉。

## 能用 Hyper 键（⌃⌥⇧⌘）吗？

可以。当录制的热键有**三个及以上修饰键**时，Kaname 接受携带其**超集**的事件。Karabiner-Elements 或 BetterTouchTool 的 Hyper 键（通常是 ⌃⌥⇧⌘）因此能触发录制的 ⌃⌥⌘ 热键。少于三个修饰键的热键严格匹配，所以两个修饰键的快捷键不会被放宽。

在 **设置 → 触发** 里照常录制热键——多出来的那个修饰键不需要额外配置。这个取舍是刻意的：三个修饰键的热键在别的工具加修饰键时也会触发。

## 怎么用键盘操作面板？

面板是持久的，所以键盘操作随时可用：

| 按键 | 动作 |
| --- | --- |
| ↑ / ↓ | 移动选中项 |
| ← / → | 上一页 / 下一页，始终可用且不可配置 |
| 执行键（默认 Space） | 关闭面板并执行选中的菜单项——在菜单里按压，只有做不到时才回放组合键 |
| 复制键（默认 Return） | 复制选中菜单项的快捷键；面板保持打开 |
| ⌫ | 撤回最后一个筛选 token——最后是字母就删字母，否则移除那个修饰键；筛选清空后再回退一段组合键 |
| Esc | 关闭面板（带不带修饰键都行） |
| 任意已启用的翻页键对（默认 `;` / `'`；可选 `,` / `.`、`[` / `]`、`-` / `=`）；⌃B / ⌃F | 上一页 / 下一页 |
| 点击 | 等同于执行键 |
| 完整快捷键 | 高亮匹配的菜单项约 0.4 秒、关闭面板，并让快捷键运行 |

两个键都在 **设置 → 通用 → 菜单项操作** 里录制，所以页脚的 `space run · ↩ copy` 永远显示你实际选的键。标点键对在同一节的**翻页导航**下：四个复选框可以自由组合（同时开几对，或一个都不开而只留方向键）；分号/引号是默认，另外三对初始不勾。它们按产生的字符而不是物理键匹配，第三对是 `-` / `=`（都不带 Shift）；`+`（Shift+=）不是翻页键，因此永远不会与 Shift 提示层的 `0`–`9` / `a`–`z` 标签冲突。搜索框获得焦点时，这些字符一个都不翻页——它们正常输入。没有按住修饰键时，导航键与两个动作键由面板消费，不会到达前台 App。⌫ 先弹出筛选的最后一个 token；队列空了再回退一段组合键，且只在没有按住其它修饰键时生效，所以 ⌘⌫ 仍是普通快捷键。

两种视觉状态容易混淆：**选中**（↑/↓ 或指针）是你自己移动的光标，而**按键高亮**标出当前前缀能到达的菜单项。一个菜单项可以被选中而不被高亮，反之亦然。选中的菜单项还会在前缘画一条 3 pt 的强调条、标题略亮，因此在浅色面板上也看得见；VoiceOver 按 名称 → 快捷键 → 状态 的顺序宣布它被选中。

对还有后续步骤的菜单项按执行键，会打开下一层而不是执行。

## 怎么清掉修饰键筛选？

面板按顺序记录你加的东西，**⌫** 一次撤回一个 token：最后加的是字母就删字母，否则移除那个修饰键。再次按**同一个修饰键**会把它从队列任意位置移除，所以 `⌃ ⌥ f` 去掉 ⌃ 就是 `⌥ f`；第三次按下又把它加回队尾。松开按键从不清空任何东西，**Esc** 关闭面板；下一次打开面板从空筛选开始，因为关闭面板就丢弃了它的筛选。要在不关闭面板的情况下拿回整张列表，一直按 ⌫ 到队列为空。

## 为什么 ⌘F 不能筛面板？

⌘F 仍是前台 App 的组合键（或是 Kaname 自己的热键之一——搜索默认是 ⌃⌥⌘F），所以它不是筛选 token。只有当那一次按键上的修饰键已经在队列里时，筛选才接受小写字母；带着队列里没有的修饰键按下的字母属于快捷键/热键路径。要用 F 收窄，请在面板打开时按 ⌃ 再按 F：队列变成 `⌃ f`，列表只留下两者都满足的菜单项。F 上多一个 ⌘ 永远不会被踩——只有已在队列里的修饰键才会把字母变成筛选 token。

## 为什么面板复制了而不是执行菜单项？

本不该如此：执行键执行菜单项。如果某个菜单项复制了，要么你按的是复制键（Return），要么在 **设置 → 通用 → 菜单项操作** 里把两个键录反了。页脚始终显示哪个键做什么，先看它一眼——并注意搜索面板是唯一 Return 永远执行、且压根没有复制键的界面。

## 按执行键为什么什么都没发生？

两种常见原因。**被禁用的菜单项**会被忽略：App 报告它不可用，就没有可执行的东西。或者目标 App 从未收到这个菜单项——在面板里，Kaname 自己按压菜单项（不切换焦点、不需要等待），所以 macOS 不允许其它进程按压的菜单项会退回回放组合键；在搜索面板里，先激活范围内的 App 再触发菜单项，所以前台化缓慢、或在自绘视图里处理该快捷键（背后没有菜单项）的 App 可能没有反应。**设置 → 通用 → 诊断 → 导出诊断包…** 加 `log show --last 5m --predicate 'subsystem == "com.suliveevil.kaname"'` 可以看出组合键是否发出、发往哪个 bundle identifier。

## 为什么面板在某些 App 或输入框里消失？

macOS 的**安全输入**开着。密码框、登录窗口与部分终端刻意对事件 tap 隐藏按键事件。Kaname 检测到就立刻隐藏，并不尝试绕过。离开安全输入框（或关掉持有安全输入的 App），面板就回来了。

## 设置与统计存在哪？怎么重置？

在 **`~/Library/Application Support/Kaname/`**，两个普通 JSON 文件——不在 UserDefaults 里：

```text
~/Library/Application Support/Kaname/
  settings.json
  usage.json
```

两者都以原子方式写入。文件无法解码时，Kaname 把它改名为 `settings.corrupt-<timestamp>.json`（或 `usage.corrupt-<timestamp>.json`）并从默认值开始，所以损坏的文件是被保留而不是被静默丢弃。**设置 → 统计 → 显示数据目录** 会在 Finder 里打开该目录，关于页也会显示它的路径。

- **只重置统计：** **设置 → 统计** 里的**重置统计**。
- **重置全部设置：** **设置 → 统计** 里的**恢复默认**，或退出 Kaname 并删除 `settings.json`。
- **删除一切：** 退出 Kaname，把整个 `~/Library/Application Support/Kaname` 拖进废纸篓。

v2.1.0 首次启动会迁移旧的 UserDefaults 数据（包括 1.x 的 `com.suliveevil.kaname` 域），只做一次。之后旧 defaults 原样留着；可用 `defaults delete com.suliveevil.kaname` 与 `defaults delete com.suliveevil.kaname` 删除。

## 重装或更新会丢设置与统计吗？

通常不会。因为数据住在 Application Support 而不是 App 的偏好域，卸载 Kaname（把 App 拖进废纸篓）、换成另一个签名的构建、或更新它，都不会删除 `settings.json` / `usage.json`。只有你手工删掉该目录、重置它，或用"彻底卸载"类工具连 Application Support 数据一起删，数据才会丢。

反过来也成立：旧的"只清偏好"命令（`defaults delete`）已经清不掉你的统计了。请删目录。

## 怎么在面板与搜索之间切换？

按**面板/搜索切换**热键——默认 ⌃⌥⌘S，可在 **设置 → 触发** 里录制。它是一个三态切换：

- 搜索可见 → 显示面板；
- 面板可见 → 显示搜索；
- 两者都不可见 → 打开面板。

两个界面**互斥**：打开一个会关闭另一个，所以屏幕上永远不会同时有两个。

## 更新后需要重新授权吗？

取决于签名：

- **v1.1 → v1.2 升级必然要求重新授予辅助功能**，因为 bundle identifier 从 `com.suliveevil.kaname` 变成了 `com.suliveevil.kaname`。如果旧条目还在，移除它并启用新 App。
- **v1.2 → v2.0 与 v2.0.0 → v2.1.0 升级不改变 bundle identifier**，所以签名更新会保留辅助功能授权。如果你跳过了某个版本，上面那条 v1.1 → v1.2 例外仍然适用。
- **Developer ID 签名并公证的发布**保留其代码身份，因此之后的更新通常保留授权。
- **ad-hoc 签名的构建**（本地构建的默认）每次重建都会换身份。macOS 可能把它当成另一个 App：从辅助功能里移除旧的 Kaname 条目（如果授过输入监控也一并移除），加入新构建，然后重启。
- 用另一个身份签名的构建替换 `/Applications/Kaname.app`，效果相同。

这是 macOS 的隐私保护，不是 Kaname 的 bug。见 [PERMISSIONS.md](PERMISSIONS.md)。

## 为什么没有 Dock 图标？

Kaname 是一个 `LSUIElement` 代理 App：住在菜单栏里，没有 Dock 图标，启动时不打开任何窗口。菜单栏图标打开面板、搜索面板与设置；⌘, 可以在它任何一个窗口里打开设置。

## 为什么设置窗口不能最小化？

因为设置只用了 `[.titled, .closable, .resizable]`。被最小化的副本过去会待在 Dock 里，而菜单栏 App 除了图标里的 **设置…** 项没有别的办法把它叫回来，而那会再打开第二个窗口。改为从菜单栏关闭再重新打开；同一个窗口会回来。设置可见时，**权限引导**会作为 sheet 附着在它上面，而不是单开一个可能跑到它后面或另一个空间里去的窗口。

## 能改触发方式或热键吗？

能。**设置 → 触发** 有两个独立开关：**修饰键手势**（按住或连按两次、触发键、按住延时）与**全局快捷键**（面板、搜索、切换三个热键）。两个都关就等于没有触发。连按的时间窗不是设置项：它跟随系统双击速度，夹在 0.25–0.6 秒之间，并且只计两次按下之间的间隔。默认值：

| 动作 | 默认 |
| --- | --- |
| 按住查看 | 按住右 Command 0.5 秒 |
| 修饰键手势 | 开 |
| 全局快捷键 | 开 |
| 面板热键 | ⌃⌥⌘K |
| 搜索热键 | ⌃⌥⌘F |
| 面板/搜索切换 | ⌃⌥⌘S |

Kaname 不重映射应用快捷键。它报告 App 已经声明的东西。

macOS 系统快捷键在这里同样只读：Kaname 在冲突列表里报告与它们的碰撞，但改不了、绑不了、也禁不掉聚焦搜索、调度中心或任何其它系统热键。

## 怎么再看一次触发提示？

首次启动显示一个 HUD——**按住 ⌘ 或连按两次打开面板**——并把 `KanameTriggerTipShown` 写进 `UserDefaults`，所以它不会重复。触发页已经没有重播按钮了；两个触发开关与它们的设置都还在。

## 统计页是怎么排序的？

**排序依据**有三个选择：**快捷键**（默认，面板的键盘顺序）、**App**、**功能描述**。选择随其它设置一起保存。页面是一张扁平列表——每个快捷键一行，所属 App 与命令作为备注写在下面——所以同一个组合键被两个 App 使用时是两行，也没有按 App 的折叠。

**它不给面板排序。** 面板遵循自己在 **设置 → 外观** 下的**面板排序**：**按修饰键**（默认——⌘ → ⌥ → ⌃ → ⇧，再按键）或**按菜单栏分组**（每个顶层菜单连续，菜单内仍按同一快捷键顺序），因为面板是一张参考卡片，而统计顺序会随着你每次改动把一个菜单项搬到别处。搜索面板同理，永远按匹配度排序。

## 能隐藏被禁用的菜单项吗？

能。`AXEnabled` 为假的菜单项默认灰显、行尾带 `lock.slash`，也可以在设置里完全隐藏。在大部分菜单都随上下文不可用的 App 里，这很有用。

## 点击灰掉的菜单项为什么会弹消息？

因为 App 报告该菜单项不可用，就没有可执行的动作。右键它会打开一个菜单，第一行在动作之上写着**该菜单项当前不可用**；点击该行也会在 HUD 里显示同一句话。这个提示有频率限制：同一菜单项最多每 3 秒解释一次，所以连点不会叠出多个相同的提示条。灰掉的行不是错误；锁图标与那句话只是在说，拒绝的是 App 自己的状态，不是 Kaname。

## 为什么面板显示的菜单项比设置里少？

**每个分组最多显示**（设置 → 外观）是上限。绘制之前，面板计算 `min(设置值, 几何可用量)`：从可用高度里减掉外框、卡片内边距、分组标题与间隙，只显示放得下的。于是 720 pt 窗口里设成 60 条，可能只显示 36 条。这是刻意的——另一种做法是把最后几条挤到页脚下面。分组标题也计入这个高度，所以打开**按菜单栏分组**可能因为多一个标题而减少可见条数。

## 改面板排序时为什么面板闪一条消息？

面板可见时在**按修饰键**与**按菜单栏分组**之间切换，会用一个单行 HUD 显示新顺序并重建列表。那是一次性公告，不是常驻徽标：面板本身不挂模式标签，所以同一块空间仍然留给菜单项。

## 为什么有些行的快捷键列是空的？

没有快捷键的菜单项就没有快捷键，所以在面板里那一列留空，而不是画一条破折号。搜索面板与 Markdown 导出会在那里画破折号，因为空白单元格看起来像渲染 bug。macOS 不公开名字的系统热键则相反：组合键本身成为行标题，快捷键列留空。该列是等宽字体里的定宽槽位，快捷键在右侧时右对齐，所以按键对齐，标题也不会随列表变化而移位。

## 面板有时出现在奇怪的位置，为什么？

这取决于 **设置 → 外观 → 面板位置**：

- **覆盖前台窗口**（默认）让面板在两个维度上都足够大以覆盖前台窗口，在该窗口上居中，并保持在可见区域内。
- **固定尺寸**用你设的宽高（默认 720 × 620）并居中。
- **铺满屏幕**用整个可见屏幕区域，停在顶部安全区之下，所以菜单栏或刘海永远不会盖住它的前几行。
- **在前台窗口旁边**是 v1.x/v2.0 的旧行为：面板贴在窗口旁或下方，尽量不盖住当前焦点元素。

几何在面板打开时计算。如果窗口之后移动了，或者某个 App 报告了异常的窗口 frame、全屏空间、多显示器让锚点混乱，面板看起来就会错位。关闭再打开，或换一种位置。

## 全屏时或切换空间后面板会跑到屏幕外吗？

不会。在空间或显示器变化之前读到的窗口 frame 会是过期的，所以面板在隐藏时、活动空间变化时、显示器变化时都丢弃缓存的锚点 frame，并在下一次展示时读新的。在读数返回之前，它用整个可见屏幕区域作为覆盖尺寸，而不是一个缩小的猜测，所以第一帧就已经完整。

在全屏空间里，可见 frame 是屏幕减掉顶部安全区——菜单栏，或带刘海的显示器上的那块刘海——面板填满该区域且不画到它下面，因此前几行与页脚都够得着。切换空间还会强制对现在位于前台的 App 重新扫描；如果 macOS 还没把那个 App 的菜单栏换回来，会保留上一张列表，而不是用空面板替换它。

## Kaname 占很多 CPU 或电池吗？

它是事件驱动的。按键 tap 在你不按键时是空闲的；菜单扫描在触发时发生并按 App 缓存 20 秒；后台没有任何轮询。如果你看到持续的 CPU 占用，留意前台 App：一个卡死且菜单庞大的 App 会让 AX 扫描很贵，直到超时生效。

macOS 系统热键列表在启动时读一次（更改界面语言后再读一次），检查更新只在你按按钮时运行。

## Kaname 会自动检查更新吗？

不会。没有后台轮询。**设置 → 关于** 有一个**检查更新**按钮；只有你按下它，Kaname 才会请求最新的 GitHub release、与正在运行的版本比较，然后要么给出发布页链接，要么说你已是最新，要么报告检查失败。它从不自行下载或安装任何东西。

## 怎么卸载 Kaname？

1. 从菜单栏退出 Kaname。
2. 把 `/Applications/Kaname.app` 拖进废纸篓。
3. 可选地移除设置与统计：

```bash
rm -rf ~/Library/Application\ Support/Kaname
defaults delete com.suliveevil.kaname        # 仅 v2.0 时代的安装
defaults delete com.suliveevil.kaname        # 仅 1.x 时代的安装
tccutil reset Accessibility com.suliveevil.kaname
tccutil reset ListenEvent com.suliveevil.kaname
```

`tccutil` 命令是可选的；它们清掉遗留的隐私条目。只有你授过输入监控时 `ListenEvent` 才有意义。`defaults` 命令只在清理旧版本写下的数据时需要；v2.1.0 把所有东西都放在 Application Support 目录里。

## 系统要求是什么？有 Windows 或 Linux 版本吗？

Kaname 需要 macOS 14 Sonoma 或更高版本。它建立在 AppKit、辅助功能与 Core Graphics 事件 tap 之上，这些全是 macOS 独有。没有 Windows 或 Linux 版本，也没有这个计划。

## 为什么快捷键和 App 自己的速查表不一样？

速查表记录的是 App 支持什么；Kaname 报告的是 App 当前在菜单栏里暴露了什么，包括启用/禁用状态与本地化菜单标题。自绘视图、网页应用与右键菜单可以支持从不出现在菜单栏里的快捷键，所以那些不会显示。反过来，菜单项可能存在但被禁用，Kaname 会把它灰显。
