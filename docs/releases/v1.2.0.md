# KagiPeek 1.2.0 — which-key style rewrite

KagiPeek now reads the frontmost app's **menu bar through Accessibility** instead of shipping a
static shortcut list, and the panel navigates prefixes the way which-key does.

## Highlights

- **Live menu scanning** — any app with a standard menu bar works, including menu grouping,
  key equivalents and enabled state. A ~100 entry built-in catalog is used as a fallback.
- **Prefix narrowing** — hold ⌘ to list ⌘ shortcuts, add ⇧ to narrow instead of closing.
- **Chords** — multi-stroke shortcuts such as ⌘K ⌘C descend one level at a time. ⌫ goes back,
  Esc closes, a breadcrumb shows where you are.
- **Next-key rows** — rows show the key to press next (`C`, `⇧S`) grouped by menu, paginated,
  with conflict markers and greyed-out unavailable items.
- **Search palette** — ⌃⌥⌘F, fuzzy search, ↵ copies the shortcut; executing the menu item is opt-in.
- **Three trigger modes** — hold modifiers (default, 0.1–1.5 s), double-tap ⌘, or a global hotkey
  (⌃⌥⌘K by default).
- **Usage statistics** — keyfreq-style counts with decay, review mode and a reset button.
- **Conflicts** — chords claimed more than once are flagged in the panel and listed in
  Settings → Ranking → Conflicts.
- **Chinese / English UI**, Reduced Transparency and Increase Contrast support, front-window
  aware positioning that avoids the focused element.
- **Engineering** — AppKit-free core in a Swift Package, 45 unit tests, GitHub Actions,
  shared scheme, release/install scripts, docs and screenshots.

## Install

Requirements: macOS 14.0 Sonoma or later.

Because this build is **not notarized** (no Developer ID certificate on the build machine),
Gatekeeper will warn on first launch. After downloading the DMG:

```sh
xattr -dr com.apple.quarantine /Applications/KagiPeek.app
open /Applications/KagiPeek.app
```

Or build from source:

```sh
git clone https://github.com/suliveevil/KagiPeek.git
cd KagiPeek
./scripts/install.sh
```

Either way, the app needs **Accessibility** on first launch (System Settings → Privacy &
Security → Accessibility). Input Monitoring is only needed if key events do not arrive.

## Upgrade notes

- The bundle identifier changed from `com.Voltline.KagiPeek` to `com.voltline.kagipeek`.
  Existing settings (language, key style, columns, launch at login) are migrated once.
- The code signature changed, so the old Accessibility grant no longer applies — re-enable
  KagiPeek under Privacy & Security.
